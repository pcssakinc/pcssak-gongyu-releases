# PCssak Gongyu 0.3.6 — Free Early Access 변경일기

이번에는 「꺼졌는데 왜 실패라고 나올까요?」라는 불편에서 시작했습니다. 0.3.5에서는 켜기가
됐다는 제보 뒤 빠른 끄기 경고가 표시됐지만 새로 고침 상태는 꺼짐이었습니다. 실제 로그도
서비스 중지와 자동 시작 차단 성공, 과거 외부 방화벽 규칙 복구 실패를 함께 보여 주었습니다.
완전 원복은 `SSH-FW/IDENTITY-MATCH-TARGET`로 멈췄습니다. 켜기 제보를 다른 PC의 SSH 로그인·
SFTP 성공으로 확대하지 않고, 일상 끄기와 과거 기록 복구의 결과를 분리하는 데 집중합니다.

아래 동작을 구현하고 개발 자동 시험으로 확인했습니다. 개발 결과와 최종 소스의 14단계·
설치본·두 업데이트 서명·정확한 9자산·공개 판독은 구분합니다. **공개 여부와 최종 검증은
해당 버전의 고정 공개 자산과 마감 기록으로 확인하세요.** 이 노트만으로 새 버전의 게시나
제보 PC의 실기 해결을 주장하지 않습니다.

## 1. 빠른 끄기는 오늘 접속을 닫는 일에 집중합니다

빠른 끄기에서 과거 외부 규칙 복구를 실행·완료 조건에서 분리합니다. PCSSAK 허용 규칙 제거,
서비스 중지·시작 유형 「사용 안 함」과 차단 상태를 실제로 다시 확인해 끄기를 판정합니다.
과거 복구가 남아 있어도 이를 서비스 중지 실패와 합쳐 표시하지 않습니다. 원본 장부는 그대로
보존하고 별도 복구 대기로 안내하며, 복구가 끝났다고 꾸미거나 원본을 자동 삭제하지 않습니다.

OpenSSH 설치·원복 기록과 SSH 켜기에서 바꾼 Private 프로필은 유지합니다. 빠른 끄기를
기능 제거·완전 원복으로 바꾸지 않으며, 이미 인증된 SSH 세션 전체가 끝났다고도 주장하지 않습니다.
서비스 상태나 차단을 확인하지 못한 실패는 여전히 검증이 필요한 실패입니다.

Windows가 서비스를 시작·중지 중이거나 일시 중지했을 때도 기존 `running=false`가 나올 수
있었습니다. 이를 중지 완료로 오인하지 않도록 SCM의 정확한 `STOPPED` 상태를 확인합니다.
서비스 기준선 원복에서 원래 중지 상태를 검증할 때도 같은 구분을 적용합니다.

## 2. 완전 원복은 끝낸 일과 보류한 일을 나눕니다

과거 외부 규칙 복구가 실패하면 완료한 서비스 중지·보호 상태까지 잃어버리는 즉시 오류 대신,
완료·보류를 구분하는 부분 결과로 이어지도록 보완합니다. 외부 복구를 확인하지 못한 상태에서는
원래 서비스 재시작·자동 시작 복원·OpenSSH 기능 제거와 보호 차단 해제를 보류합니다.
실패를 단순히 숨기고 계속 진행하는 방식이 아닙니다.

서비스 중지와 필요한 보호 상태를 다시 확인한 부분 결과만 일반 재시도로 이어지도록 합니다.
안전을 확인하지 못한 상태는 중단 복구 검증이 필요합니다. 원래 사용자 설치 OpenSSH와 설정은
보존하고, 외부 복구 실패를 완전 원복 성공이나 모든 PC의 복구 보장으로 표시하지 않습니다.

## 3. 사라진 정확한 V5 대상은 확인·승인 뒤 원본을 보관합니다

이전 실패의 `native_target_not_unique`만으로는 대상이 없었는지 여러 개였는지 구분할 수
없었습니다. 조회 단계와 대상 수를 고정 진단으로 나누고, 규칙 이름·ID·주소·개인 경로 같은
원문을 공개 오류에 싣지 않는 방향으로 보완합니다.

이제 정확한 ID가 없음을 이중 확인한 뒤 미리보기의 승인 해시와 일치하는 명시적 사용자
승인을 받아 원본을 관리자 보호 저장소에 보관합니다. 존재하는 대상, 정책 변경, 중복 대응과
조회 실패는 단순 누락으로 처리하지 않고 원본을 보존합니다. 승인 뒤 규칙이나 기록이 동시에
바뀌면 진행하지 않습니다. 보관 중 중단되면 이미 남긴 원본과 진행 기록으로 이어갑니다.

원본 보관은 사라진 Windows 규칙을 복원했다는 뜻이 아닙니다. 이 동작으로 실제 규칙을
변경하거나 재생성하지 않으며, 보관 건수와 완전 원복 완료를 구분합니다. 구형 중단 기록이
남았을 때도 종류에 맞는 다음 복구 단계로 연결해, 같은 막힌 작업만 반복하거나 원본을 지워
우회하지 않도록 했습니다. 개발 검증을 실제 PC의 복구 성공으로 바꾸지 않습니다.

## 4. 익숙한 보호와 기존 설치는 그대로 지킵니다

0.3.5의 PCSSAK 소유 차단 규칙 다섯 건인 LAN 보호막을 유지합니다. 켜기와 빠른 끄기는 다른
프로그램·Windows 기본 허용 규칙을 임의로 끄거나 복구하지 않습니다. 로컬 정책 적용 가능성,
인증 우회 없음과 제외 인터페이스 없음을 확인한 범위만 안전으로 판단하며, 알 수 없는 상태를
안전으로 바꾸거나 조직 정책 전체의 효과를 보장하지 않습니다. VPN·가상 어댑터를 SSH 신뢰
범위에 넣지 않으며 VPN 경유 SSH와 인터넷 포트 포워딩은 지원하지 않습니다.

설치 재부팅 대기는 전체 100%·접속 성공이 아닙니다. 재부팅 뒤 SSH 켜기를 다시 실행해
나머지 설정을 확인합니다. 서비스 등록 표시와 Windows 기능 설치 상태도 구분합니다.
현재 PC의 sshd 배너 응답은 다른 PC의 접속·패킷 차단 검증을 대신하지 않습니다.
앱 제거는 SSH 환경을 자동 원복하지 않으므로 미해결 기록과 결과를 먼저 확인해야 합니다.

## 5. 설치기와 배포 안내도 함께 맞춥니다

제품의 Cargo·잠금 항목·Tauri 버전을 0.3.6으로 맞추고 설치기에 0.3.5에서 보호 교체하는
네 진입 경로를 추가합니다. 기존 버전 허용, 소유 표식 확인, 잘못된 버전 거부, 분기·시험 상수
누락, 교체 실패와 중단 뒤 원래 버전·설정·복구 기록 보존을 기존 두 NSIS 검사에 추가합니다.
제3자 고지는 0.3.6 Cargo.lock으로 다시 생성했으며 의존성 버전·법률 정본·업데이트
공개키는 바꾸지 않습니다. 과거 불변 릴리스·자산·노트도 보존합니다.

한영 매뉴얼·보안 안내·공개 템플릿을 같은 구분으로 갱신했습니다. 빠른 끄기와 외부 복구 대기,
안전한 부분 원복 재시도, V5 조회·명시 승인 보관·다음 복구 연결을 10개 언어에서 구분합니다.
번역이나 모의 회귀만으로 실제 PC 성공을 주장하지 않습니다.

## 설치와 앱 내 업데이트

- 설치 파일은 `PCssak-Gongyu-0.3.6-Windows-x64-Setup.exe`입니다.
- 법률 정본과 업데이트 공개키를 바꾸지 않습니다. 정상 법률 동의 기록이 남은 0.3.5 사용자는 앱에서 새 버전을 확인하고 다운로드·서명 검증·사용자 승인 후 업데이트할 수 있습니다.
- 0.1.0에는 앱 내 업데이트가 없으므로 공식 설치본을 한 번 수동 설치해야 합니다.
- MPL 원본 이름: `PCssak-Gongyu-0.3.6-MPL-Sources.zip`
- 공개 대상: Windows x64. Windows x86 설치본은 공개하지 않습니다.

정상 법률 동의 기록이 있는 공개 0.2.0~0.2.8·0.3.2~0.3.5와 비공개 0.2.9·0.3.0·0.3.1은
실제 공개 후 앱에서 다운로드·서명 검증·사용자 승인형 업데이트를 사용할 수 있습니다.
0.1.9는 현행 법률 문서를 확인하는 대화형 설치, 0.1.8 이하는 이전 공개키 전환에 따른
수동 설치가 필요합니다. 서명 오류를 우회하지 마세요.

0.1.1~0.3.5는 먼저 제거하거나 설정·공유·SSH·중단 기록을 지우지 않고 보호 교체합니다.
0.1.0만 별도 제거 후 설치하며, 동의·설치 기록을 확인하지 못하면 대화형 안내를 따릅니다.
설치 자체가 복구 장부를 삭제하거나 SSH를 자동으로 켜지 않습니다.

## 검증한 것과 아직 확인하지 못한 것

개발 Windows x64 Rust 전체 시험은 **1,028개 통과·0 실패·23 수동 제외**였고 Clippy x64도
통과했습니다. 빠른 끄기와 과거 복구의 분리, 외부 복구 실패 뒤 기준선 적용 보류, 안전 상태에
따른 재시도 분류와 V5 보관 경로를 개발 검증에 포함했습니다. 이 수치는 개발 소스의 결과이며
최종 설치본이나 실제 PC의 완료 증거가 아닙니다.

최종 소스를 동결한 뒤 Windows x64·i686 시험, 양쪽 Clippy, 정적·UI·보안 감사·릴리스 빌드 등
필수 14단계의 결과를 별도로 결속합니다. GitHub Actions 시간을 사용하지 않는 승인된 로컬 검증은
도구·소스·계획·각 종료 코드와 원문 로그 해시로 남기며 Actions 성공으로 표시하지 않습니다.
그 뒤 설치본 두 업데이트 서명·정확한 아홉 자산·익명 공개 판독을 별도로 확인해야 합니다.
과거 버전이나 중간 소스의 통과 수치를 이번 설치본의 증거로 재사용하지 않습니다.

새 버전의 실제 설치·업데이트·제거, 현재 PC의 켜기·끄기·완전 원복·V5 보관 적용,
두 물리 PC의 SSH 로그인·SFTP·공유, 실제 방화벽 등록·패킷 차단과 재부팅은 `NOT_RUN`입니다.
0.3.5 사용자 제보와 기존 로그 판독은 이번 버전의 실기 해결 증거가 아닙니다.

`0.1.2 <= 버전 <= 0.4.9`는 무료 Early Access이며 다음 제한을 유지합니다.

- Windows Authenticode 게시자 서명이 없습니다. Windows가 실행을 막을 수 있습니다.
- Windows 10/11 Home·Pro 전체 실기 검증이 완료되지 않았습니다.
- 실제 두 PC의 SSH/SFTP 실기 검증이 완료되지 않았습니다.
- 외부 법률 검토가 완료되지 않았습니다.
- 독립 공급망 검토가 완료되지 않았습니다.

기존 키의 Tauri 업데이트 서명, 별도 Minisign 서명과 SHA-256은 계속 필수지만
Windows 게시자 신원을 대신하지 않습니다. 보안 프로그램을 끄지 마세요.
복구 가능한 시험 PC에서 최신 백업과 보안 제품을 유지하며 확인하세요. 실패가 반복되면
앱·설정·복구 기록을 보존하고 진단 코드를 확인하세요. 방화벽 초기화, 기록 삭제나 보안
해제로 우회하지 마세요. 모든 환경에서의 무결함·접속 성공·보안 보장을 주장하지 않습니다.
