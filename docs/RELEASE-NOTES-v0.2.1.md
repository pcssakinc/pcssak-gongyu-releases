# PCssak Gongyu 0.2.1 — 무료 Early Access

0.2.1은 SSH 방화벽 준비와 재설치 후 재사용, 공유·저장 연결 화면의 잘못된 대상 처리,
기존 버전의 보호 교체를 개선합니다. 사진으로 제보된 PC의 원인을 확정한 것은 아니며,
같은 오류로 이어질 수 있는 코드 결함을 재현하여 수정했습니다.

## SSH 방화벽과 재설치 재개

- 같은 이름·조건의 활성 규칙과 비활성 규칙을 서로 혼동하여 변경 전 검증에서 중단하던
  결함을 수정했습니다. Windows 정책 저장소와 고유 규칙 ID로 구별하고 원래 꺼져 있던
  다른 규칙은 켜지 않습니다. 전체 정책을 대조하고 필요한 활성 상태만 변경합니다.
- 유일하게 대응되는 기존 복구 기록을 새 형식으로 이어받습니다. 이전 원복이 중단된 뒤
  다시 켤 때 현재 상태를 별도로 기록하고, 실패하면 이번 호출 직전 상태로 되돌립니다.
  앱을 삭제하고 재설치해도 남아 있는 정상 기록을 지우지 않고 재사용합니다.
- IPv4·IPv6 단일 주소와 동일한 접두사 표현, 혼합 주소 목록의 표기 차이를 처리합니다.
  서로 다른 주소·범위를 같다고 허용하지 않습니다. 처리할 규칙과 기록이 모두 없으면
  불필요한 추가 조회를 생략합니다.
- Windows의 변경 요청이 아직 끝나지 않았는데 반대 원복을 먼저 실행하는 경합을 막습니다.
  실제 실패의 단계별 진단은 로컬 로그에 남기며 안전 오류를 숨기지 않습니다.
- 원본 규칙을 유일하게 구별할 수 없거나 외부에서 정책을 바꾼 경우에는 추정 복원하지
  않습니다. 조직의 방화벽 정책이나 Windows 자체 장애를 무조건 우회하는 기능이 아닙니다.

## 설치와 앱 내 업데이트

- 설치 파일은 `PCssak-Gongyu-0.2.1-Windows-x64-Setup.exe`입니다.
- 법률 정본과 업데이트 공개키를 바꾸지 않습니다. 정상 법률 동의 기록이 남은 0.2.0 사용자는
  앱에서 새 버전을 확인하고 다운로드·서명 검증·사용자 승인 후 업데이트할 수 있습니다.
- 0.1.9 사용자는 현행 사용권 계약·개인정보 처리방침의 확인이 필요하므로 공식 설치본을
  직접 실행합니다. 0.1.8 이하도 공식 설치본을 한 번 직접 실행하는 전환이 필요합니다.
- 0.1.1~0.2.0은 업데이트 전에 먼저 제거하지 않습니다. 새 설치본이 사용자 설정을 보존하고
  기존 앱 파일을 보호 교체합니다. 이미 제거했다면 공식 설치본을 다시 설치할 수 있으며,
  남은 SSH 복구 기록이나 Windows 설정을 임의로 지우지 마세요.
- 0.2.0의 보호 교체 허용 누락을 백업·중단 복구·대화형 교체·재설치 네 경로에서 수정했습니다.
- 0.1.0에는 앱 내 업데이트가 없으므로 공식 설치본을 한 번 수동 설치해야 합니다.
- 0.1.0만 별도의 구 버전 제거 후 설치가 필요합니다. 동의 기록이 없거나 설치가 손상된 경우에는
  대화형 설치로 확인하며 새 동의가 필요한 설치를 무인 진행하지 않습니다.

## 공유와 저장 연결 화면

- 서로 다른 공유의 코드 발급 요청이 공용 권한 창을 덮어써 첫 버튼이 계속 대기하는 문제를
  수정했습니다. 취소·잠금·목록 교체 뒤에는 이전 권한 선택과 지연 포커스를 폐기합니다.
- IP를 바꾼 뒤 이전 장치의 MAC 응답이 새 장치에 붙지 않도록 했습니다. 수동 입력과
  저장 중 새로 작성한 폼은 보존하고 추가 버튼의 중복 저장을 막습니다.
- 공유 목록 저장 실패 때 편집창을 유지해 다시 시도할 수 있게 했습니다. 이전 저장의 늦은
  완료가 새 대상의 편집창이나 다음 입력을 닫지 않도록 했습니다.
- 저장 자격증명 창의 요청을 시작 당시 장치·공유에 고정했습니다. 취소·잠금·대상 변경 뒤
  이어지는 마운트·삭제를 중단하고, 이미 시작한 쓰기가 끝나기 전에 중복 쓰기를 막습니다.
  취소가 이미 완료된 Windows 작업이나 저장을 원복한다는 뜻은 아닙니다.
- 백업 파일을 읽는 동안 앱을 잠갔다면 이전 가져오기·덮어쓰기 확인을 이어서 실행하지
  않습니다. 중복 가져오기·내보내기를 막고 실패 후 같은 파일로 다시 시도할 수 있습니다.
- 직접 연결 자격증명 창도 시작 당시 대상을 유지합니다. 이전 연결 응답이 새 창의 암호를
  지우거나 잘못된 대상의 성공 처리를 호출하지 않도록 했습니다.

## 보안과 지원 범위

공개 설치본은 Windows x64 전용입니다. SSH는 신뢰하는 같은 물리 LAN용이며 VPN·가상
어댑터를 신뢰 범위에서 제외합니다. Windows 방화벽을 끄거나 모든 출발지에 포트를 여는
방식은 사용하지 않습니다. 공용 물리 LAN 신뢰와 관리자 권한의 필요한 동의를 유지합니다.
카페·호텔·공항·게스트 Wi-Fi를 신뢰 LAN으로 전환하지 마세요.

기존 OpenSSH는 다시 사용합니다. 켜기는 서비스 실행과 자동 시작을 함께 확인하고,
끄기는 서비스 중지·사용 안 함 시작 유형·보호 규칙을 확인합니다. 완전 원복은 별도 기능이며
앱이 직접 설치한 소유 증거가 있는 OpenSSH만 제거 대상입니다. 다른 프로그램이 설치한
서비스·사용자 설정·외부 방화벽 규칙을 일괄 삭제하지 않습니다.

Windows Authenticode 게시자 서명이 없습니다. Tauri 업데이트 서명·Minisign 서명·SHA-256은
무결성을 검증하지만 Windows 게시자 신뢰를 대신하지 않습니다. Windows·보안 제품은
실행을 막을 수 있습니다. 보안 제품·조직 정책을 우회하지 마세요. 보안 프로그램을 끄지 마세요.
실제 파일의 해시·서명이 다르면 실행하지 마세요.

## 검증 범위와 남은 실측

관리자 승인으로 `0.1.2 <= 버전 <= 0.4.9`는 무료 공개 Early Access로 제공합니다.

수정 과정에서 생산 UI 처리기 모의 시험 283개, Rust x64 시험 760개, 실제 NSIS의 더미
버전 분기 640사례를 통과했습니다. 개발 PC의 기존 SSH 기록 3개도 새 고유 ID와 정책으로
유일하게 대응됨을 읽기 전용으로 확인했습니다. 이 수치는 실제 제품 설치나 SSH 접속 시험이
아닙니다. 최종 동결 소스의 검증 증거와 공개 자산 검증은 별도로 결속합니다.

- Windows 10/11 Home·Pro 전체 실기 검증이 완료되지 않았습니다.
- 실제 두 PC의 SSH/SFTP 실기 검증이 완료되지 않았습니다.
- 외부 법률 검토가 완료되지 않았습니다.
- 독립 공급망 검토가 완료되지 않았습니다.
- 실제 사용자 PC의 설치·일반 제거·공유 연결·SSH 로그인·SFTP·재부팅 지속성은 배포 후 확인합니다.

재현한 코드 결함의 자동 시험과 현재 개발 PC의 읽기 전용 확인을 다른 PC의 접속 성공으로
표시하지 않습니다. 복구 가능한 시험 PC에서 최신 백업과 함께 사용하세요. 조직 정책,
설치 원본 부재, 다른 서비스의 포트 점유, 계정 인증 실패까지 항상 자동 해결한다고 보장하지
않습니다. 최종 소스 검증과 불변 9자산·법률 정본·MPL 원본 결속을 마친 뒤에만 공개합니다.
