# PCssak Gongyu 0.4.1 — Free Early Access 변경일기

랜선을 연결하고 인터넷도 사용하는데 공유 자동설정이 연결 문제로 멈추면, 무엇을
확인해야 할지 알기 어려웠습니다. 기존에는 서로 다른 연결 판정 실패를 하나의
「네트워크가 변경되었습니다」 안내로 바꾸고 있었습니다. 0.4.1은 실제 판정 이유를
보존해 다음 확인 사항을 구분하고, 설정 화면의 복구 안내를 정리합니다.

## 공유 연결에서 막힌 이유를 구분

공유 자동설정과 공유 생성의 연결 확인에서 주소·경로·어댑터·프로필 조회 등으로
생긴 일곱 종류의 하위 원인을 공유용 오류로 구분합니다. 단순한 조회 실패를 케이블
분리나 실제 네트워크 변경으로 단정하지 않고, 같은 오류 문구만 반복하지 않도록
안내합니다. 공개 로그에 원시 주소·장치 이름·네트워크 식별자를 추가하지 않습니다.

신뢰 동의한 네트워크 식별자와 앱이 돌려주는 연결 범위는 같은 시점에 조회한 결과에
묶습니다. 별도 조회 결과가 섞여 승인한 연결과 실제 적용 범위가 달라지는 것을 막고,
적용 직전과 적용 후의 검증은 유지합니다. 동의한 연결이 달라지거나 확정되지 않으면
진행하지 않습니다.

서비스가 시작되는 동안 같은 LAN의 주소가 갱신돼도, 방금 검증한 최신 주소로
공유 포트 준비를 확인합니다. 새 상태를 확인하고도 예전 주소를 기다리던 결함을
수정했습니다. 다른 연결이나 신뢰하지 않은 Public 상태를 허용하는 변경은 아닙니다.

물리 LAN, 지원 주소, 직접 연결 경로와 네트워크 프로필의 기존 검증 기준은
완화하지 않습니다. VPN·가상 어댑터를 자동으로 신뢰하거나 인터넷 사용만으로
공유 가능한 연결이라고 판단하지 않습니다. 정확히 식별한 Public 물리 LAN은
해당 연결의 신뢰 동의를 받은 뒤에만 Private 전환을 진행하며, 공공망에서는
동의를 취소해야 합니다.

이번 계기가 된 원격 서버는 사용자가 물리 서버임을 확인했지만 정확한
오류·버전·운영체제·연결 구조가 아직
확인되지 않았습니다. 원격 접속, Windows Server, Hyper-V 또는 팀 NIC 자체가
실패 원인이라고 확정하지 않았으며, 해당 환경의 지원 확대나 해결 완료를
약속하는 변경은 아닙니다.

## 설정의 복구 안내를 읽기 쉽게

설정의 복구 카드에서 현재 상태, 수행할 수 있는 조작과 추가 설명을 구분해
정리합니다. 상태를 읽거나 조작을 고르기 전에 긴 설명을 모두 읽어야 하는 불편을
줄입니다. 사용자 확인, 중복 실행 방지와 중단된 작업의 보호는 유지하며, 화면을
정리했다고 남은 복구를 완료로 표시하거나 자동으로 실행하지 않습니다.

0.4.0에서 정리한 일반 SSH 켜기·끄기·우리 SSH 설정 원복과 기본 설정 분류는
유지합니다. 과거 방화벽 기록의 특수 복구 화면을 다시 추가하지 않습니다.

## 기존 설정과 부분 원복의 경계

현재 LAN 규칙의 소유권, 설치 전 SSH 서비스 상태와 원복에 필요한 보호 기록을
유지합니다. 0.3.9부터의 보호된 **부분 원복** 한계도 그대로입니다. 과거 타사 규칙
복구가 독립적으로 남았고 보호 원문과 대상의 비중첩을 확인한 경우에만 앱 소유
허용 규칙과 설정을 정리하며, 수신 서비스를 중지한 채 보호 차단을 유지할 수 있습니다.

과거 규칙의 원래 활성 상태, 설치 전 서비스 상태, 앱이 설치한 OpenSSH 기능 제거,
Public 프로필 복원과 보호 차단 해제는 보류될 수 있습니다. 손상된 기록, 겹치는
대상이나 읽을 수 없는 상태를 성공으로 바꾸지 않습니다. 「우리 설정 정리」가
PC 전체의 설치 전 상태 복원을 뜻하지 않으며, 장부를 직접 지우거나 중단 복구
도중 구버전 실행 파일로 강제 복귀하지 마세요.

## 설치와 업데이트

0.3.9의 법률 정본과 업데이트 공개키를 그대로 사용합니다. 0.3.9·0.4.0에서 정상
법률 동의 기록을 확인할 수 있으면 공식 0.4.1 공개 후 앱에서 업데이트할 수 있습니다.
다운로드·서명 검증·사용자 승인은 계속 필요합니다. 업데이트 자체가 SSH를 켜거나
중단된 복구를 완료하지는 않습니다.

- 설치 파일은 `PCssak-Gongyu-0.4.1-Windows-x64-Setup.exe`입니다.
- 법률 정본과 0.3.9의 업데이트 공개키를 바꾸지 않습니다. 정상 법률 동의 기록이 남은 0.3.9·0.4.0 사용자는 앱에서 새 버전을 확인하고 다운로드·서명 검증·사용자 승인 후 업데이트할 수 있습니다.
- 0.3.8 이하 사용자는 현행 업데이트 공개키가 없으므로 공식 0.4.1 설치본을 한 번 직접 내려받아 대화형으로 설치해야 합니다.
- 0.1.1~0.4.0 사용자는 기존 앱을 먼저 제거하거나 설정·공유 장부·SSH 설정·중단 기록을 지우지 않고 공식 설치본을 기존 설치 위에 보호 덮어 설치합니다.
- 0.1.0에는 앱 내 업데이트와 보호 덮어 설치를 지원하지 않으므로 구 버전을 제거한 뒤 공식 0.4.1 설치본을 직접 설치해야 합니다.
- 구형 앱에는 현행 공개키가 없어 서명 오류가 표시될 수 있습니다. 서명 검증을 우회하지 말고 공식 홈페이지나 버전 고정 GitHub 릴리스를 이용하며 설치본의 SHA-256을 공개 목록과 대조하세요.
- 버전 고정 MPL 원본: PCssak-Gongyu-0.4.1-MPL-Sources.zip
- Windows x86 설치본은 실제 Windows 10 x86 시험 전에는 공개하지 않습니다.

설치기는 기존 0.4.0도 보호 교체 대상으로 확인합니다. 업데이트·중단 복구·대화형
설치·재설치의 네 경로에 같은 버전 확인을 적용하며, 실패하면 원본과 설정을 보존하는
계약을 유지합니다. 새 버전 안내의 자동 업데이트 대상, 구키 앱의 수동 설치와
보호 교체 범위도 검사합니다. 이전 공개 버전의 노트와 자산은 변경하지 않습니다.

## 확인한 것과 아직 확인하지 못한 것

연결 원인 구분, 승인 범위 결속, 설정 화면과 설치·업데이트 계약의 검증은 최종
고정 소스의 실제 결과로 판정합니다. 예정된 검사 수치를 완료 실적으로 쓰지 않으며,
개발 회귀, 최종 검증, 설치본 빌드·두 서명·정확한 아홉 자산과 공개 확인을 구분합니다.

0.4.1 설치본의 실제 설치·업그레이드·제거, 재부팅과 두 물리 PC의 SSH/SFTP·VPN
공존·완전 원복 실기는 **NOT_RUN**입니다. 원격 서버에서 공유 자동설정이 성공하는지
확인하는 실기도 **NOT_RUN**입니다. 이전 버전 사용자 경험을 새 설치본의 성공 증거로
사용하지 않습니다. Windows 10/11 Home·Pro 전체 행렬, 외부 법률 검토와 독립 공급망
검토도 미완료입니다. 복구 가능한 시험 PC와 최신 백업에서 먼저 확인해 주세요.

- Windows Authenticode 게시자 서명이 없습니다. Windows가 실행을 막을 수 있습니다.
- Windows 10/11 Home·Pro 전체 실기 검증이 완료되지 않았습니다.
- 실제 두 PC의 SSH/SFTP 실기 검증이 완료되지 않았습니다.
- 외부 법률 검토가 완료되지 않았습니다.
- 독립 공급망 검토가 완료되지 않았습니다.
- 공개 자산의 Tauri 업데이트 서명, 별도 Minisign 서명과 SHA-256을 검증합니다.
  복구 가능한 시험 PC에서 사용하세요. 보안 프로그램을 끄지 마세요.

업데이트 서명은 파일 무결성 확인이며 Windows 게시자 신원 서명을 대신하지 않습니다.
