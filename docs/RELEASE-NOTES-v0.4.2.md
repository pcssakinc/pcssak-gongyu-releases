# PCssak Gongyu 0.4.2 — Free Early Access 변경일기

설정이 끝난 뒤에도 가상 네트워크 때문에 다시 준비하라는 안내가 나오고, 화면의 색과
설명이 제품마다 달라 낯설게 느껴질 수 있었습니다. 이번에는 0.4.1의 연결·복구 보호를
유지하면서 실제 물리 LAN을 보는 기준과 PCSSAK의 화면 언어를 맞췄습니다. 먼저 보존해
둔 개선 후보에 최신 브랜드 정체성, 가독성, 사용 설명과 0.4.1 보호 업데이트를 더했습니다.

## PCSSAK다운 화면과 읽기 쉬운 조작

크림은 넓은 배경, 네이비는 글과 중요한 조작, 민트는 작은 강조로 역할을 나눴습니다.
S 아래 두 선의 워드마크와 제품 설명을 함께 사용하고, 운영체제 기본 글꼴을 적용합니다.
Windows 설정 따르기·밝게·어둡게와 기본·큰 글자를 선택할 수 있으며, 저장한 설정을
처음 그릴 때부터 읽어 다른 색이 잠깐 나타나는 현상을 줄입니다. 구형 네 가지 테마와
직접 색상 선택은 새 밝기 설정으로 이어집니다. 직접 색상의 밝기 의도를 보존하지만
기존 색상 조합 자체를 그대로 재현하지는 않습니다. 기본 글자 크기는 16에서 14픽셀로
바뀌며 더 큰 글자를 선택할 수 있습니다.

보조 버튼의 경계를 카드 구분선과 나누고 고대비 환경의 키보드 초점선을 보완합니다.
버튼을 구분할 수 있도록 글·경계·초점을 함께 사용합니다. 화면을 다듬어도 SSH 실행
권한, 사용자 확인, 설정 복구 순서와 중단 기록 보호를 바꾸지는 않습니다.

## 이미 준비된 물리 LAN의 자동설정 판정

자동설정의 Public 집계를 실제 동의하고 전환할 물리 LAN과 같은 기준으로 맞춥니다.
물리 LAN은 이미 준비됐는데 VPN·가상 어댑터만 Public인 이유로 설정을 반복하려던
판정을 줄입니다. 조회가 실패하면 준비 완료라고 추정하지 않습니다. 물리 LAN·직접
연결 경로·프로필과 정확한 승인 대상의 변경 전후 검증은 유지합니다.

전환이나 절전 복귀 직후의 일시적인 조회 실패에는 1.2초의 재시도를 한 번 더 둡니다.
총 대기는 최대 1.7초이며 확정적인 주소·프로필 오류는 반복하지 않습니다. 모든 설정을
더 빠르게 하는 변경은 아니며, 기다릴 수 있는 일시적 상황만 유한하게 보완합니다.

## 여러 방화벽 규칙을 읽는 보조 조회

조건부 보조 조회에서 일곱 종류의 필터를 일괄 읽고 고유 ID로 결합합니다. 첫 규칙을
공식 개별 조회와 대조하고 불일치가 있으면 해당 관측의 일괄 결과를 폐기합니다.
누락·중복·공급자 실패는 기존 개별 조회로 돌아가며 복구 중지 요청은 그대로 전달합니다.
정확 ID의 원복 대상과 변경 전후 검증은 기존 개별 판독을 유지합니다.

개발 PC의 읽기 전용 대조는 48개 이름·83개 규칙의 결과가 같고 쓰기가 없었습니다.
이번 참고 측정은 일괄 46.422초·개별 54.197초로 다른 검사와 겹친 한 번의 수치입니다.
다른 환경의 약 22배 조회 개선을 이 PC나 일반 SSH 켜기·끄기·원복 전체에 적용하지
않습니다. 정상 조작은 새 보조 경로를 사용하지 않는 경우가 많습니다.

## 현재 버튼에 맞춘 설명과 실패 안내

열 언어의 OpenSSH 설치 소스와 COM 안내에서 환경의 원인을 단정하던 문구를 고칩니다.
내장 한·영 설명서는 현재 켜기·끄기·우리 설정 원복을 구분하고 퇴역한 과거 복구 화면을
현재 사용법으로 안내하지 않습니다. 앱 종료·업데이트만으로 SSH가 자동으로 꺼지거나
켜지지는 않습니다. 관리형 켜기는 자동 시작·실행 상태를 만들고 빠른 끄기는 서비스
중지·시작 유형 사용 안 함을 확인합니다. 재부팅 후에는 서비스의 실제 상태를 확인하세요.

## 기존 설정과 해결되지 않은 복원의 경계

0.4.1의 연결 실패 일곱 원인, 같은 조회 결과에 묶인 신뢰 동의·적용 범위, 최신 주소
대기와 상태·조작을 먼저 보여 주는 설정 복구 화면을 유지합니다. 0.4.0에서 퇴역한
과거 방화벽 복구 화면과 WebView 권한을 다시 열지 않으며 보호 기록을 지우지 않습니다.

0.3.9부터의 보호된 **부분 원복** 한계는 그대로입니다. 과거 타사 규칙 복구가 독립적으로
남았고 보호 원문·정확 대상의 비중첩을 확인한 경우에만 앱 소유 허용·설정을 정리합니다.
과거 규칙의 활성 상태, 원래 서비스 상태, OpenSSH 기능 제거, Public 프로필 복원과
보호 차단 해제는 보류될 수 있습니다. 손상·부재·같은 이름의 다른 ID·중복·정책 변화는
이번 버전에서 해결됐다고 표시하지 않습니다. 우리 설정 정리가 설치 전 PC 전체의
완전 복원을 뜻하지 않으며 장부를 직접 지우지 마세요. 원격 서버 실패 원인과 해당
환경의 해결 여부도 미확인입니다. 다른 프로그램과 Windows 기본 규칙을 임의로
바꾸지 않고 조직 정책 전체의 우선순위나 모든 SSH 세션 종료를 보장하지 않습니다.

## 설치와 업데이트

0.3.9의 법률 정본과 업데이트 공개키를 그대로 사용합니다. 정상 법률 동의 기록이
남은 0.3.9·0.4.0·0.4.1 사용자는 공식 0.4.2 공개 후 앱에서 다운로드·서명 검증·사용자
승인으로 업데이트할 수 있습니다. 업데이트가 SSH를 켜거나 과거 복구를 완료하지는 않습니다.

- 설치 파일은 `PCssak-Gongyu-0.4.2-Windows-x64-Setup.exe`입니다.
- 법률 정본과 0.3.9의 업데이트 공개키를 바꾸지 않습니다. 정상 법률 동의 기록이 남은 0.3.9·0.4.0·0.4.1 사용자는 앱에서 새 버전을 확인하고 다운로드·서명 검증·사용자 승인 후 업데이트할 수 있습니다.
- 0.3.8 이하 사용자는 현행 업데이트 공개키가 없으므로 공식 0.4.2 설치본을 한 번 직접 내려받아 대화형으로 설치해야 합니다.
- 0.1.1~0.4.1 사용자는 기존 앱을 먼저 제거하거나 설정·공유 장부·SSH 설정·중단 기록을 지우지 않고 공식 설치본을 기존 설치 위에 보호 덮어 설치합니다.
- 0.1.0에는 앱 내 업데이트와 보호 덮어 설치를 지원하지 않으므로 구 버전을 제거한 뒤 공식 0.4.2 설치본을 직접 설치해야 합니다.
- 구형 앱에는 현행 공개키가 없어 서명 오류가 표시될 수 있습니다. 서명 검증을 우회하지 말고 공식 홈페이지나 버전 고정 GitHub 릴리스를 이용하며 설치본의 SHA-256을 공개 목록과 대조하세요.
- 버전 고정 MPL 원본: PCssak-Gongyu-0.4.2-MPL-Sources.zip
- Windows x86 설치본은 실제 Windows 10 x86 시험 전에는 공개하지 않습니다.

설치기의 자동 업데이트 준비·중단 복구·대화형 설치·재설치 네 경로에 기존 0.4.1의
정확 버전 분기를 추가합니다. 실패·중단 시 기존 파일과 설정·기록 보존을 유지합니다.
이전 공개 태그·자산·업무일지는 변경하지 않습니다.

## 확인한 것과 아직 확인하지 못한 것

개발 회귀와 읽기 전용 동등성, 최종 고정 소스의 검증, 설치본·두 업데이트 서명·정확한
아홉 자산·공개 판독을 각각 확인합니다. 예정 수치를 완료 실적으로 쓰지 않습니다.
0.4.2 설치본의 실제 설치·업그레이드·제거·재부팅·두 물리 PC SSH/SFTP·VPN 공존·완전
원복, 실패 회사 PC에서의 성공 확인과 Windows 10/11 Home·Pro x64 전체 행렬은
**NOT_RUN**입니다. 이전 버전에서 성공한 경험을 이번 설치본의 실측으로 바꾸지 않습니다.

외부 법률 검토·전체 실기 행렬·독립 공급망 승인·Windows 게시자 Authenticode 서명과
타임스탬프는 미완료입니다. 설치기와 내부 앱이 모두 미서명인지 확인하는 Early Access
계약과 Tauri/Minisign 업데이트 서명·SHA-256 검증은 생략하지 않습니다. 복구 가능한
시험 PC·최신 백업에서 먼저 확인하고 보안 제품은 유지해 주세요.

- Windows Authenticode 게시자 서명이 없습니다. Windows가 실행을 막을 수 있습니다.
- Windows 10/11 Home·Pro 전체 실기 검증이 완료되지 않았습니다.
- 실제 두 PC의 SSH/SFTP 실기 검증이 완료되지 않았습니다.
- 외부 법률 검토가 완료되지 않았습니다.
- 독립 공급망 검토가 완료되지 않았습니다.
- 공개 자산의 Tauri 업데이트 서명, 별도 Minisign 서명과 SHA-256을 검증합니다.
  복구 가능한 시험 PC에서 사용하세요. 보안 프로그램을 끄지 마세요.

업데이트 서명은 파일 무결성 확인이며 Windows 게시자 신원 서명을 대신하지 않습니다.
