# PCssak Gongyu 0.3.7 — Free Early Access 변경일기

「예전에는 접속까지 됐는데, 이제는 무엇을 눌러도 안 됩니다.」 이번에는 이 제보와 화면에서
다시 출발했습니다. 앞선 버전에서 SSH 켜기와 실제 접속을 확인했다는 사용자 보고는 그대로
남깁니다. 다만 그 성공을 이번 버전의 끄기·원복·업데이트 성공으로 대신할 수는 없습니다.

0.3.6에서는 중단된 전체 원복과 그 안에서 먼저 처리해야 하는 방화벽 복구가 서로를 막는
연결 결함을 확인했습니다. 자동 점검이 「외부 규칙 복구 필요」를 알려 준 다음, 원복 재개와
재조회 버튼까지 계속 비활성 상태로 남는 화면 결함도 있었습니다. 이번 수정은 기록을 지워
처음부터 다시 설치하는 대신, 남겨 둔 기록을 따라 필요한 단계부터 이어가는 데 집중합니다.

아래는 구현 내용과 개발 검증 범위입니다. **최종 소스 검증·설치본·두 업데이트 서명·정확한
9자산·공개 판독은 해당 버전의 고정 릴리스와 마감 기록으로 확인하세요.** 이 노트만으로
새 버전의 게시나 제보 PC의 실제 복구 성공을 주장하지 않습니다.

## 1. 전체 원복이 멈춰 있어도 필요한 방화벽 복구로 이어집니다

이전에는 SSH 켜기·끄기·완전 원복의 중단 기록이 남으면 별도 방화벽 복구 명령도 「다른
작업이 남아 있다」며 시작하지 못했습니다. 반대로 자동 점검은 방화벽 복구가 끝나지 않았기
때문에 원래 작업을 해제하지 않았습니다. 각 기능을 따로 검사하는 것만으로 놓친 연결 문제입니다.

이제 방화벽 복구는 중단된 SSH 작업의 같은 ID와 종류를 유지한 채 필요한 하위 단계로 실행할
수 있습니다. 구형 외부 규칙 복구와, 정확한 ID가 사라진 V5 항목의 승인 보관 모두 이 진입을
사용합니다. 같은 시간에 다른 변경은 실행되지 않으며, 실제 적용 전 대상과 승인 내용을 다시
대조합니다. SSH 이외 작업의 중단, 손상된 기록, 권한 부족은 이 경로로 우회하지 않습니다.

사라진 항목의 보관은 실제 Windows 방화벽 규칙을 되살렸다는 뜻이 아닙니다. 원본을 보호
보관하고 승인한 부재 항목만 활성 장부에서 분리하는 기존 계약을 유지합니다. 현재 존재하는
규칙을 이름으로 대신 선택하거나, 읽기 오류를 부재로 취급하지 않습니다.

## 2. 작은 단계가 끝났다고 전체 원복을 완료 처리하지 않습니다

방화벽 하위 단계가 끝나도 원래 SSH 작업은 미완료로 남습니다. 사용자가 원래 작업을 재개하면
서비스·설정·남은 복구 상태를 다시 검증합니다. 하위 단계 성공을 전체 성공으로 바꾸거나
자동으로 SSH를 켜지 않습니다. 예전에 켜기를 시작했다가 끄기로 이어진 경우도 처음 작업의
기록을 유지합니다.

실패, 부분 응답, 호출 중단, 워커 오류와 업데이트 설치 예약이 끼어드는 경우도 같은 원칙을
따릅니다. 보호된 원본과 진행 기록을 남기고 동시 변경을 막습니다. 원래 작업을 다시 이어갈
수 있게 하는 것과 검증 없이 잠금을 풀어 버리는 것을 구분했습니다.

## 3. 자동 점검 뒤 다시 사용할 수 있는 버튼을 돌려줍니다

자동 점검 중에는 원복 재개·재조회·중복 점검을 잠시 막습니다. 점검이 끝나면 최신 상태에
맞춰 세 버튼을 함께 갱신합니다. 「외부 규칙 복구 필요」라는 점검 결과는 그대로 보여 주면서,
실행 가능한 원복 재개와 재조회는 다시 사용할 수 있게 했습니다.

점검 뒤 상태 조회 자체가 실패했다면 재조회만 열고, 오래된 상태를 근거로 원복을 실행하지
않습니다. 앱 잠금이나 다른 작업 진행 중에도 버튼을 임의로 열지 않습니다. 기존 10개 언어의
안내와 문구는 재사용하며, 이번에는 버튼 상태를 결정하는 공통 처리와 연결 회귀를 보완했습니다.

## 4. 업데이트가 기존 SSH 설정을 초기화하지는 않습니다

정상 업데이트와 프로그램 종료는 SSH 설치·설정을 지우거나 서비스를 끄지 않습니다.
PC가 꺼진 동안에는 접속할 수 없고, 다시 켰을 때의 시작 여부는 Windows 서비스 시작 설정을
따릅니다. PCSSAK 관리 켜기는 자동 시작을 설정하지만, 사용자가 설치한 SSH를 단순 제어하는
경로는 원래 시작 유형을 보존합니다. 사용자가 빠른 끄기를 실행했다면 그 꺼짐 상태도 유지합니다.

이번 설치기는 0.3.6에서 보호 교체하는 네 진입 경로를 추가합니다. 먼저 제거하거나 설정·공유·
SSH·복구 기록을 지우지 마세요. **남은 중단 기록 때문에 앱 안 업데이트가 막히면 공식 0.3.7
설치본을 직접 실행해 보호 교체하세요.** 설치가 기록을 삭제하거나 SSH 복구를 완료하지는
않습니다. 업데이트 후 남은 복구 안내에 따라 필요한 단계를 이어갑니다.

버전·Tauri 설정·Cargo 잠금의 제품 항목, 제3자 고지·MPL 원본 이름과 한영 공개 안내를 함께
맞췄습니다. 의존성 버전·법률 정본·업데이트 공개키는 유지합니다. 이전 불변 릴리스의 파일과
노트도 바꾸지 않습니다. 설치기 회귀에는 이전 버전 분기 누락, 잘못된 버전·소유 표식,
교체 실패·중단 뒤 원래 버전과 설정·복구 기록 보존을 포함합니다.

## 설치와 앱 내 업데이트

- 설치 파일: `PCssak-Gongyu-0.3.7-Windows-x64-Setup.exe`
- MPL 원본: `PCssak-Gongyu-0.3.7-MPL-Sources.zip`
- 공개 대상: Windows x64. Windows x86 설치본은 공개하지 않습니다.
- 정상 법률 동의와 작업 상태 확인을 통과한 0.3.6 사용자는 실제 공개 후 다운로드·서명 검증·사용자 승인형 앱 내 업데이트를 사용할 수 있습니다.

정상 법률 동의 기록이 있는 공개 0.2.0~0.2.8·0.3.2~0.3.6과 비공개 0.2.9·0.3.0·0.3.1은
같은 업데이트 계약을 따릅니다. 0.1.9는 현행 법률 문서를 확인하는 대화형 설치, 0.1.8 이하는
이전 공개키 전환에 따른 수동 설치가 필요합니다. 서명 오류를 우회하지 마세요.
0.1.1~0.3.6은 보호 교체하며 0.1.0만 별도 제거 후 설치합니다. 동의·설치 기록을 확인하지
못하면 대화형 안내를 따릅니다.

## 검증한 것과 아직 확인하지 못한 것

이번 기능 수정의 개발 Windows x64 Rust 전체 시험은 **1,034개 통과·0 실패·23 수동 제외**,
화면 시험은 **508개 통과**였습니다. 부모 작업 보존, 다른 변경과의 경합, 방화벽 하위 단계의
성공·실패·부분 응답, 자동 점검 종료 뒤 버튼 상태를 회귀 시험으로 확인했습니다. 실제 작업
저널을 사용하는 연결 시험을 추가해, 개별 함수 통과를 사용자 동선의 성공으로 대신하지 않게
했습니다. 이 수치는 버전·설치기를 포함한 최종 배포 소스 검증과 구분합니다.

최종 소스를 고정한 뒤 Windows x64·i686 시험, 양쪽 Clippy, 정적·UI·보안 감사·릴리스 빌드 등
필수 14단계 결과를 별도로 결속합니다. 승인된 외장 로컬 환경의 도구·소스·종료 코드·원문 로그
해시를 남기며 GitHub Actions 러너의 성공으로 표시하지 않습니다. 설치본 두 업데이트 서명,
정확한 아홉 자산과 익명 공개 판독도 별도 확인 대상입니다.

새 설치본의 실제 설치·업데이트·제거, 현재 PC의 SSH 켜기·끄기·완전 원복·V5 보관 적용,
두 물리 PC의 SSH 로그인·SFTP·공유, 실제 방화벽 등록·패킷 차단과 재부팅은 `NOT_RUN`입니다.
사용자가 이전에 접속을 확인했다는 보고와 이번 자동 시험을 .37의 모든 환경 성공으로 바꾸지
않습니다. 개선점은 이번에 확인한 연결 결함이며 속도 향상 수치를 주장하지 않습니다.

`0.1.2 <= 버전 <= 0.4.9`는 무료 Early Access이며 다음 제한을 유지합니다.

- Windows Authenticode 게시자 서명이 없습니다. Windows가 실행을 막을 수 있습니다.
- Windows 10/11 Home·Pro 전체 실기 검증이 완료되지 않았습니다.
- 실제 두 PC의 SSH/SFTP 실기 검증이 완료되지 않았습니다.
- 외부 법률 검토가 완료되지 않았습니다.
- 독립 공급망 검토가 완료되지 않았습니다.

기존 키의 Tauri 업데이트 서명, 별도 Minisign 서명과 SHA-256은 계속 필수지만 Windows
게시자 신원을 대신하지 않습니다. 보안 프로그램을 끄지 마세요. 기존 사용자 SSH와 PCSSAK 소유 LAN 보호막을 보존하고,
판독 실패를 안전으로 표시하지 않습니다. VPN 경유 SSH와 인터넷 포트 포워딩은 지원하지
않습니다. 최신 백업과 보안 제품을 유지하며 복구 가능한 시험 PC에서 확인하세요. 실패가
반복되면 원본 기록과 진단을 보존하고, 방화벽 초기화·장부 삭제·보안 해제로 우회하지 마세요.
