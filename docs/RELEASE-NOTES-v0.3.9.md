# PCssak Gongyu 0.3.9 — Free Early Access 변경일기

0.3.8에서는 이 PC의 SSH 켜기·끄기·재켜기까지 확인했습니다. 하지만 오래전에 시작한
타사 방화벽 복구가 남아 있으면 「SSH 완전 원복」이 첫 단계에서 막혔습니다. 조회도 한 번
누른 뒤 같은 Windows 상태를 여러 차례 확인해 오래 걸렸고, 화면에는 지난 상태나 짧게
끊긴 경과 시간이 남았습니다. 이번에는 이 경험에서 출발해 평소 SSH 조작과 과거 복구를
각각 제자리로 돌려놓았습니다.

## SSH를 켜고 끌 때

- 켜기 준비에서 같은 시점의 엄격한 방화벽 조회를 공유해 중복 확인을 줄였습니다.
  변경 직전과 변경 후의 새 검증은 생략하지 않습니다. 따라서 모든 PC에서 몇 초 만에
  끝난다고 약속하지는 않습니다.
- 작업 중 예전 「켜짐」 또는 「꺼짐」 결과가 현재 진행을 덮지 않게 했습니다. 긴 조회의
  완료 응답과 진행 시간도 같은 작업에 이어 표시합니다.
- 중단된 과거 타사 규칙 복구는 보호된 원문·승인·대상 ID와 현재 앱 소유 SSH 규칙의
  비중첩을 확인한 경우에만 일반 SSH 조작과 분리합니다. 기록을 지우거나 그 복구를
  완료했다고 표시하지 않습니다. 자기 SSH 작업 자체가 중단된 경우에는 원래 작업을
  확인해 재개하며 다른 작업으로 바꾸지 않습니다.

## 「우리 설정 원복」을 누를 때

이전에는 독립적인 과거 타사 방화벽 복구가 미완료라는 이유만으로 우리 앱이 만든
SSH 설정 정리도 시작할 수 없었습니다. 이제 보호 기록과 대상이 서로 겹치지 않음을
확인하면 앱 소유 허용 규칙과 설정을 정리하고, 수신 서비스를 중지한 채 보호 차단을
유지합니다. 실제로 확인한 정리 결과와 아직 남은 타사 복구를 다른 상태로 알려줍니다.

이 상태는 **부분 원복**입니다. 과거 규칙의 원래 활성 상태 복원, 설치 전 서비스 시작
유형·실행 상태 복원, 앱이 설치한 OpenSSH 기능 제거, Public 프로필 복원과 보호 차단
해제는 보류합니다. 타사 기록이 손상됐거나 현재 규칙과 겹치거나 정확한 상태를 읽지
못하면 자동으로 밀어붙이지 않습니다. 기존 장부와 작업 기록을 보존해 별도의 복구를
다시 확인할 수 있게 합니다. 이 구분 덕분에 「우리 설정 정리」가 끝났다는 문구를
「PC가 설치 전 상태로 완전히 돌아왔다」는 뜻으로 오해하지 않게 했습니다.

## 화면과 계정 표시

- 과거 복구 상세에서 현재 조회의 취소·안전 중지에 접근하기 쉽게 하고, 처음 누른
  뒤의 총 경과 시간을 이어 표시합니다. 이미 시작된 Windows 호출을 강제로 죽이거나
  그 호출이 끝나기 전에 원복 완료를 선언하지 않습니다.
- 왼쪽 하단 IP 아래에 현재 앱이 열린 Windows 로그인 세션의 계정을 표시합니다.
  관리자 재실행 계정이나 원격 SSH 로그인 계정과 같은 의미가 아닙니다. 조회할 수
  없으면 「확인 불가」로 표시하고, 계정값을 새 진단 기록으로 보관하지 않습니다.
- 부분 원복과 별도 복구 필요 안내를 지원하는 10개 화면 언어에 반영했습니다.

## 설치와 업데이트

0.3.8의 법률 정본은 유지하지만 업데이트 서명키는 새로 만듭니다. 기존 0.3.8 이하
앱에는 새 공개키가 없으므로 앱 안에서 0.3.9를 검증해 설치할 수 없습니다. 공식
0.3.9 설치본이 공개된 뒤 홈페이지 또는 버전 고정 GitHub 릴리스에서 직접 내려받아
대화형으로 설치해야 합니다. 기존 설치·SSH 설정·계정 키·공유 장부·중단 기록을
임의로 지우지 마세요. 새 작업 기록은 구버전이 이해하지 못할 수 있으므로 중단 복구
도중 이전 버전 실행 파일로 강제 복귀하지 마세요. 업데이트 자체가 SSH를 켜거나 과거
방화벽 복구를 완료하지는 않습니다.

- 설치 파일은 `PCssak-Gongyu-0.3.9-Windows-x64-Setup.exe`입니다.
- 업데이트 서명키 전환으로 0.3.8 이하 사용자는 공식 0.3.9 설치본을 한 번 직접 내려받아 대화형으로 설치해야 합니다.
- 0.1.1~0.3.8 사용자는 기존 앱을 먼저 제거하거나 설정·공유 장부·SSH 설정·중단 기록을 지우지 않고 공식 설치본을 기존 설치 위에 보호 덮어 설치합니다.
- 0.1.0에는 앱 내 업데이트와 보호 덮어 설치를 지원하지 않으므로 구 버전을 제거한 뒤 공식 0.3.9 설치본을 직접 설치해야 합니다.
- 법률 정본은 바꾸지 않습니다. 설치 화면에서 필요한 동의를 확인하고, 0.3.9부터 새 키로 서명한 후속 버전만 앱에서 다운로드·서명 검증·사용자 승인 후 설치할 수 있습니다.
- 구형 앱에는 새 공개키가 없어 서명 오류가 표시될 수 있습니다. 서명 검증을 우회하지 말고 공식 홈페이지나 버전 고정 GitHub 릴리스를 이용하며 설치본의 SHA-256을 공개 목록과 대조하세요.
- 버전 고정 MPL 원본: PCssak-Gongyu-0.3.9-MPL-Sources.zip
- Windows x86 설치본은 실제 Windows 10 x86 시험 전에는 공개하지 않습니다.

0.1.8 이하의 더 오래된 공개키 경로와 0.1.9의 법률 확인 경로를 거친 사용자도
이번에는 새 키를 받으려면 위 공식 설치본을 직접 설치해야 합니다.

## 확인한 것과 아직 확인하지 못한 것

개발 과정에서 화면 모의 시험과 정적 계약 검사를 실행했습니다. 외장 Windows 검증,
최종 소스의 x64·i686 Rust 시험, 설치본·두 업데이트 서명·정확한 아홉 공개 자산의
결과는 해당 SHA의 최종 검증 기록으로 판정합니다. 시험용 외장 exFAT에서 Windows
접합점 생성이 불가능해 실패한 ACL 회귀시험은 작은 임시 시험 자료만 NTFS에 두도록
수정하고 두 임시 경로에서 다시 확인했습니다. 이 시험 환경 수정은 Windows SSH
동작의 실측 증거가 아닙니다.

0.3.9 설치본의 실제 설치·업그레이드·제거, 재부팅 뒤 SSH 상태, 두 물리 PC의
SSH/SFTP와 타사 방화벽 복구·완전 원복 연속 실기는 **NOT_RUN**입니다. 0.3.8에서
확인한 한 PC의 켜기·끄기·재켜기를 이번 설치본의 성공으로 옮겨 적지 않습니다.
Windows 10/11 Home·Pro 전체 행렬, 외부 법률 검토, 독립 공급망 검토와 Windows
Authenticode 게시자 서명도 미완료입니다. 무료 Early Access의 실제 이용은
복구 가능한 시험 PC와 최신 백업에서 먼저 확인하고 보안 제품을 유지해 주세요.
Tauri와 별도 Minisign 업데이트 서명은 파일 무결성을 위한 것이며 Windows 게시자
신원 서명을 대신하지 않습니다.

- Windows Authenticode 게시자 서명이 없습니다. Windows가 실행을 막을 수 있습니다.
- Windows 10/11 Home·Pro 전체 실기 검증이 완료되지 않았습니다.
- 실제 두 PC의 SSH/SFTP 실기 검증이 완료되지 않았습니다.
- 외부 법률 검토가 완료되지 않았습니다.
- 독립 공급망 검토가 완료되지 않았습니다.
- 공개 자산의 Tauri 업데이트 서명, 별도 Minisign 서명과 SHA-256을 검증합니다.
  복구 가능한 시험 PC에서 사용하세요. 보안 프로그램을 끄지 마세요.
