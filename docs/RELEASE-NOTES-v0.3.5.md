# PCssak Gongyu 0.3.5 — 남의 방화벽 규칙을 끄지 않고 LAN 보호막으로 지키는 변경일기

## 이번 변경을 시작한 이유

0.3.4를 설치한 뒤 이전에 SSH 설정이 되지 않던 PC 일부에서는 켜기가 끝났다는 보고를
받았습니다. 그러나 방화벽 문제로 분류돼 온 PC에서는 SSH 켜기를 시작하면 여전히 같은
오류로 멈춘다는 제보가 이어졌습니다. 확보한 기록에서 그 PC는 켜기 2%의 구형 방화벽
기록 검사에서 막혔고, 「이전 방화벽 기록 복구」는 25개 그룹 가운데 첫 그룹의 대조
실패로 전체가 끝나 「대조 0/25」로 남았습니다.

원인 분석은 이 현상을 Windows나 다른 프로그램과의 충돌로 보지 않았습니다. 0.2.4부터 이
앱이 스스로 떠안은 계약 — 다른 프로그램과 Windows 기본 규칙 가운데 TCP 22를 넓게 허용하는
규칙을 잠시 끄고 나중에 정확히 되돌린다 — 이 문제였습니다. 그 계약은 규칙의 정체를
Windows가 보장하지 않는 표시 문자열의 완전 일치로 정의했고, 0.2.4~0.3.4의 같은 계열
수정은 모두 그 계약을 유지한 채 대조 정확도를 높이는 방향이었기 때문에 실패 지점만 옮겨
다녔습니다. 84%에서는 네트워크 판정 실패가 방화벽 오류로 보고돼 조사 축마저 흐려져
있었습니다.

이번 0.3.5는 **그 계약 자체를 폐기합니다.** SSH 켜기는 더 이상 다른 프로그램이나 Windows의
방화벽 허용 규칙을 임시로 비활성화하지 않습니다. 대신 PCSSAK 소유의 인바운드 차단 규칙
다섯 건(「LAN 보호막」)으로 승인된 물리 LAN 밖의 접속을 막습니다. 제보된 PC의 문제가
해결됐다고 발표하는 버전은 아니며, 실제 PC에서 확인하기 전까지 그렇게 주장하지 않습니다.

## 남의 방화벽 규칙을 끄지 않고 LAN 보호막을 세웁니다

SSH를 켤 때 PCSSAK 허용 규칙보다 먼저 인바운드 차단 규칙 다섯 건을 만듭니다. 0.3.4의 허용
계약(승인된 물리 LAN IPv4 안의 원격 주소 × 물리 IPv4 로컬 주소 × Domain·Private 프로필 ×
유선·무선 인터페이스 × 실제 `sshd.exe`)의 각 조건을 뒤집어 하나씩 차단 규칙으로 만든 것입니다.

- `PCSSAK Gongyu SSH Non-LAN Block` — sshd.exe로 오는 접속 가운데 원격 주소가 승인된 LAN IPv4
  서브넷 밖(여집합, 시작-끝 범위)이거나 IPv6이면 차단합니다.
- `PCSSAK Gongyu SSH Public Profile Block` — Public 프로필에서는 주소와 무관하게 sshd.exe 접속을
  차단합니다(같은 번호대의 공용 Wi-Fi로 옮겨도 열리지 않습니다).
- `PCSSAK Gongyu SSH Remote Access Block` — VPN·원격 액세스 인터페이스로 도착한 sshd.exe
  접속을 차단합니다(VPN 주소가 집 LAN과 겹쳐도 열리지 않습니다).
- `PCSSAK Gongyu SSH Non-Physical Local Block` — 이 PC의 승인된 물리 IPv4가 아닌 로컬 주소
  (가상 어댑터·IPv6)로 도착한 sshd.exe 접속을 차단합니다.
- `PCSSAK Gongyu TCP 22 Non-LAN Block` — 프로그램과 무관하게 TCP 22로 오는 LAN 밖 접속을
  차단합니다. 포트 프록시나 다른 SSH 서버가 22번을 대신 받아도 LAN 밖에서는 닿지 못합니다.

Windows 방화벽은 인바운드에서 명시적 차단 규칙을 충돌하는 일반 허용 규칙보다 먼저 적용합니다.
이 [Microsoft 공식 규칙 우선순위](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules)를
이용해 다른 프로그램의 규칙을 끄고 되돌리던 부담을 줄였습니다. 단, 로컬 방화벽 정책을 실제로
적용할 수 있어야 하며 인증된 연결의 차단 우회나 방화벽 제외 인터페이스가 없어야 합니다.
조직 정책이 로컬 규칙 적용을 거부하는 환경을 우회하지 않으며, 모든 GPO·MDM·보안 제품 조합에서
같이 작동한다고 주장하지 않습니다.

보호막은 등록 뒤 규칙을 다시 읽어 검증합니다. 주소는 표시 문자열의 동등이 아니라 범위 집합으로
비교하므로 Windows가 순서·마스크·단일/범위 표기를 바꿔 돌려줘도 같은 집합이면 통과하고, 다른
집합이면 실패합니다. 다섯 규칙이 각각 정확히 한 건이고, 프로그램·프로토콜·포트·프로필·
인터페이스·활성 상태가 모두 계약과 같으며, 특정 NIC·원격 포트·패키지·사용자 같은 추가 제약이
붙지 않았을 때만 보호막이 성립합니다. 승인된 LAN 목록을 해석하지 못하거나 IPv6가 섞였거나
여집합이 비어 보호막이 아무것도 막지 못하는 경우에는 허용 규칙을 만들지 않고 켜기를 중단합니다.
고정 진단 코드는 `LAN-SHIELD-SCOPE`(범위 계산 실패), `LAN-SHIELD`(재판독 불일치),
`LAN-SHIELD-UPGRADE`(0.3.4 활성 계약에 보호막만 추가하는 승격 실패)입니다.

알려진 제한이 있습니다. Windows의 「Override block rules」(IPsec으로 인증된 연결에만 허용되는
규칙의 차단 우회 옵션)는 차단 규칙보다 먼저 평가됩니다. 0.3.5는 인증 조건(SecureFlags)이 붙은
sshd 적용 가능 허용 규칙을 보수적으로 「보호막이 막지 못하는 규칙」으로 판정해 안전하지 않음으로
표시하며(오탐 허용), 로컬 저장소에 보이지 않는 그룹 정책 배포 우회 규칙은 판정 범위 밖입니다.
보호막은 IPv6 전체를 막으므로 SSH가 켜진 동안 IPv6(링크 로컬 포함)로는 sshd에 접속할 수
없습니다(PCSSAK 허용 규칙도 IPv4 전용입니다). 다섯째 규칙은 sshd가 아닌 다른 프로그램의 TCP 22도
LAN 밖에서 막습니다. 승인된 LAN이나 이 PC의 IPv4 주소가 바뀌면 보호막은 이전 LAN 기준이므로
상태 카드가 안전하지 않음으로 표시되며(실제로는 이전 LAN 밖 전부를 막는 과잉 안전 상태),
「SSH 접속 켜기」를 다시 누르면 현재 LAN으로 다시 세웁니다. Windows가 여집합 표기
(`0.0.0.0-…`, `…-255.255.255.255`, IPv6 전체 범위)는 Windows의 미등록 임시 COM 규칙 객체에서
설정·재조회했습니다. 원격·로컬 주소 범위, Public 프로필, RemoteAccess 유형 네 사례가
통과했고 실제 방화벽에 추가한 규칙은 없습니다. 실제 규칙 등록과 패킷 차단 효과는 별도 실기로
확인해야 합니다.

## 켜기와 이전 외부 규칙 복구를 분리합니다

켜기를 시작하기 전에 구형(V4) 방화벽 기록의 대응 가능 여부를 검사하던 관문과, 임시로
꺼야 할 외부 허용 규칙이 4건을 넘는지 미리 세던 관문을 없앴습니다. 첫 관문은 제보된 PC가
2%에서 멈추던 지점이고, 둘째 관문은 켜기가 외부 규칙을 끄지 않는 이상 의미가 없습니다.
승인된 복구가 적용 중인 상태만 여전히 켜기를 보류합니다. 외부 허용 규칙이 몇 건이든 켜기는
진행합니다. 그 목록은 보호막과 전체 안전 판정이 모두 확인된 경우에만 상태 카드에
「LAN 보호막이 막고 있는 외부 허용 규칙」으로 표시하며 규칙을 끄거나 바꾸지 않습니다.
판정하지 못한 속성이나 인증 우회가 있으면 위험 안내를 유지합니다. 방화벽 행은 「허용 규칙과 LAN 보호막 활성」 또는
「허용 규칙만 있음 · LAN 보호막 없음」으로 보호막 상태를 드러냅니다. 열 개 언어에 새 문구 아홉 개를
같은 자리표시자로 추가하고 쓰이지 않게 된 문구 하나를 제거했습니다. 복구 승인·완료 안내도
열 개 언어에서 미해결 원인을 정확히 구분하도록 고쳤습니다.

켜기와 기존 활성 상태의 보호막 추가는 이전 버전이 끈 외부 규칙을 자동으로 되살리지
않습니다. 이 작업을 함께 실행하면 긴 구형 기록 대조 때문에 켜기가 다시 지연되거나,
보호막 검증 뒤 인증 우회 규칙이 활성화될 수 있어 분리했습니다. 기존 기록과 활성 상태를
보존하며 「이전 방화벽 기록 복구」에서 확인 후 처리합니다. 끄기·완전 원복은 서비스와
차단 상태를 확인한 기존 원복 절차를 따릅니다. 기존에 꺼졌던 다른 프로그램의 규칙이
이번 켜기만으로 모두 복구되는 것은 아닙니다.

보호막과 전체 안전 판정이 모두 확인된 경우에만 외부 규칙 목록을 보호 중으로 표시합니다.
인증 우회 속성을 읽지 못하거나 기본 속성이 불완전한 잠재 적용 규칙은 보호막만으로
안전하다고 판단하지 않습니다. 실제 활성 프로필에서 Windows 방화벽 적용을 제외한
인터페이스가 있으면 보호막 효과를 확인할 수 없다고 알리며, VPN이 있다는 이유만으로
거부하지는 않습니다. 실패 원복에서 서비스 중지를 확인하지 못하면 새 보호막을 남기고,
보호막 원복 미완료 상태에서 서비스 재시작이나 전체 차단 해제를 진행하지 않습니다.

0.3.4 이하로 SSH를 켠 PC는 허용 규칙만 있고 보호막이 없습니다. 화면의 「이미 켜져 있습니다」
단축은 보호막까지 서 있을 때만 쓰므로, 이런 PC에서 「SSH 접속 켜기」를 누르면 앱이 켜기를 실제로
호출합니다. 서비스·자동 시작·허용 규칙·기준선이 현재 계약과 같고 보호막만 없으면 전체 차단·
네트워크 전환·서비스 변경 없이 보호막 다섯 건만 추가하고 전체 계약을 다시 읽어 끝냅니다. 이
승격이 실패하면 이번에 만든 보호막만 지우고 호출 전 상태로 돌아갑니다. 조건이 다르면(허용 규칙이
다른 LAN에서 만든 것 등) 일반 재켜기로 진행하며, 그때도 OpenSSH가 설치돼 있으면 DISM 설치를
생략합니다. 실패 원복의 기준선 판정은 보호막과 무관하므로, 0.3.4로 켠 활성 계약이 재켜기 실패
때문에 허용 규칙만 남고 서비스는 꺼진 상태로 끝나지 않습니다.

구형(V4) 기록 검사가 켜기 관문에서 빠지면서 「이전 방화벽 기록 복구」 카드로 가는 유일한 진입점도
사라졌으므로, 상태 조회가 구형 기록을 읽어 카드를 보이도록 했습니다. 보호된 완료 기록이
마감까지 끝났고 현재 장부와 정확히 일치하면 카드를 다시 띄우지 않습니다. 손상·불일치·마감 중인
기록은 완료로 추측하지 않습니다. 이 조회는 외부 규칙을 변경하지 않습니다.

## 이전 방화벽 기록 복구를 항목별로 대조합니다

「이전 방화벽 기록 복구」는 이전에 첫 그룹의 대조 불일치에서 전체가 실패했습니다. 제보된
PC의 「대조 0/25」가 그 결과입니다. 이제 판정하지 못한 그룹만 미해결(변경하지 않고 기록
보존)로 두고 나머지 그룹을 계속 대조·복구합니다. 미해결 이유는 규칙 없음, COM 대응
불명확·변경, 정책 저장소 대응 불명확·변경, 활성 상태 변경, 패키지 규칙 원본 비활성의
다섯 가지 고정 코드로 집계해 이유별 건수만 화면과 로그에 표시합니다. 규칙 이름·주소·경로는
싣지 않습니다. 저장된 복구 계획의 형식은 바꾸지 않아 0.3.4가 남긴 진행 중 기록도 계속
읽습니다. 미해결 그룹을 임의로 대응시키거나 외부 규칙을 새로 만들지 않는 기존 원칙은
유지합니다. 잔여 계획의 4건 상한도 없앴습니다(켜기가 외부 규칙을 끄지 않으므로 상한이 지킬 것이
없습니다). 미해결 그룹의 원본은 보호된 복구 기록 안에 남지만 활성 기록에서는 빠지므로, 그 규칙이
이전 버전 때문에 아직 비활성 상태라면 Windows 방화벽에서 직접 확인해 켜야 합니다. 미해결 이유와
건수는 승인 전 확인 화면과 복구 완료 문구에 모두 표시됩니다. 모두 「규칙 없음」이라고
안내하던 번역도 고쳤습니다. 이미 완료된 복구를 조회하면 완료 내용을 보여 주며 다시 승인하거나
적용하지 않습니다. 원본 기록을 지워 복구가 끝난 것처럼 처리하지 않습니다.

## 실패 위치와 실제 응답을 구분해 보고합니다

84% LAN 규칙 단계에서 물리 LAN 판정에 실패하면 방화벽 오류가 아니라 네트워크 진단 키로
보고합니다. 이전에는 Public 프로필이나 판정 불가 같은 네트워크 원인이 방화벽 안전 검사
실패로 표시돼 원인 축이 섞였습니다. 물리 LAN 판정 실패의 단계 코드(`NETWORK-SCOPE` 계열)는
네트워크 안내 문구에서도 그대로 표시됩니다.

켜기가 끝나면 이 PC 자신의 승인된 LAN IPv4 주소로 TCP 22에 접속해 sshd 배너 응답을
확인하고 결과 문구에 싣습니다. 「이 PC에서 sshd 응답을 확인했습니다」는 sshd가 실제로
접속을 받았다는 뜻이며, 다른 PC에서의 방화벽 경로 검증은 아닙니다. 3초 안에 응답을 받지
못하면 「아직 확인하지 못했습니다」로만 표시하고 켜기 실패로 처리하지 않습니다. 인증은
시도하지 않고 배너만 읽은 뒤 연결을 닫습니다.

## 끄기와 완전 원복이 보호막도 제거합니다

빠른 끄기는 전체 차단 규칙을 먼저 세우고 PCSSAK 허용 규칙을 제거한 뒤 서비스를 중지·비활성화합니다.
LAN 보호막과 이전 버전이 끈 외부 규칙의 원복은 그 뒤, 전체 차단이 검증됐거나 서비스 중지와 시작
유형 「사용 안 함」이 확인된 경우에만 처리합니다. 그 전에 보호막을 지우면 남의 넓은 허용 규칙만
남는 순간이 생기기 때문입니다. 보호막 제거를 검증하지 못하면 「LAN 보호막은 안전을 위해
유지했습니다. 다음 끄기 재시도에서 정리됩니다」를 함께 표시하며, 보호막은 추가 차단일 뿐이므로
끄기 완료 판정은 바꾸지 않습니다. 완전 원복은 모든 복원 검증이 끝난 마지막 단계에서 보호막을
먼저, 전체 차단 규칙을 그다음에 제거하고, 보호막 제거를 검증하지 못하면 전체 차단을 유지한 채
부분 완료로 끝내 같은 버튼의 재시도로 잇습니다. 서비스가 없는 PC의 끄기는 남은 보호막을 먼저
지우고 그 부재까지 확인된 경우만 변경 없는 완료로 봅니다. 보호막은 관리 규칙 흔적 조회에도
포함됩니다.

앱 제거는 0.3.4까지와 같이 SSH 서비스와 PCSSAK 방화벽 규칙을 남기며, 보호막 다섯 규칙도 함께
남습니다. SSH를 계속 쓰는 사용자를 위한 정책이며, 앱만 지우고 보호막이 남으면 남의 허용 규칙이
살아 있어도 LAN 밖은 계속 막힙니다. SSH가 더 필요 없으면 제거 전에 「SSH 환경 완전 원복」을
실행하세요. 앱 제거 뒤 직접 지우려면 Windows Defender 방화벽 고급 보안의 인바운드 규칙에서
`PCSSAK Gongyu`로 시작하는 규칙(위 다섯 건과 `PCSSAK Gongyu SSH TCP 22 In`)을 확인해 삭제합니다.

## 기존 설치와 업데이트 경로를 보존합니다

설치기에 공개 0.3.4에서 0.3.5로 보호 교체하는 네 진입 경로를 추가했습니다. 버전 분기
누락, 잘못된 버전 문자열, 소유 표식 불일치, 교체 실패와 중단 뒤 복구를 두 NSIS
회귀시험에 포함합니다. 이 시험은 제품을 실제 설치하는 시험과 구분합니다.

Cargo·Tauri 제품 버전, 제3자 고지와 MPL 원본 이름을 0.3.5로 맞춥니다. 의존성 버전·법률
정본·업데이트 공개키는 바꾸지 않습니다. 제3자 고지와 MPL 원본은 최종 잠금파일과 실제
버전에 맞춰 생성·검증해야 합니다.

## 설치와 앱 내 업데이트

- 설치 파일은 `PCssak-Gongyu-0.3.5-Windows-x64-Setup.exe`입니다.
- 법률 정본과 업데이트 공개키를 바꾸지 않습니다. 정상 법률 동의 기록이 남은 0.3.4 사용자는 앱에서 새 버전을 확인하고 다운로드·서명 검증·사용자 승인 후 업데이트할 수 있습니다.
- 0.1.0에는 앱 내 업데이트가 없으므로 공식 설치본을 한 번 수동 설치해야 합니다.
- MPL 원본 이름: `PCssak-Gongyu-0.3.5-MPL-Sources.zip`
- 공개 대상: Windows x64. Windows x86 설치본은 공개하지 않습니다.

정상 법률 동의 기록이 있는 공개 0.2.0~0.2.8·0.3.2~0.3.4와 비공개
0.2.9·0.3.0·0.3.1 사용자는 실제 공개 후 앱에서 다운로드·서명 검증·사용자 승인형
업데이트를 사용할 수 있습니다. 0.1.9는 현행 법률 문서를 확인하는 대화형 설치,
0.1.8 이하는 이전 공개키 전환에 따른 수동 설치가 필요합니다.

0.1.1~0.3.4는 기존 앱을 먼저 제거하거나 설정·공유·SSH·중단 기록을 지우지 않고
보호 교체합니다. 0.1.0만 별도 제거 후 설치하며, 동의·설치 기록을 확인하지 못하면
대화형 안내를 따릅니다. 설치만으로 복구 기록을 삭제하거나 SSH를 자동으로 켜지 않습니다.
이전 불변 릴리스와 자산은 보존합니다.

## 확인한 범위와 남은 확인

개발 중 확인은 다음을 대상으로 합니다. Windows x64 대상 컴파일 검사는 Linux 컨테이너에서
오류와 경고 없이 끝났습니다. 보호막의 순수 계산부(여집합·범위 집합 비교·실패 폐쇄 입력)는
Windows 없이 실행되는 시험으로 확인했고, 화면 회귀시험은 보호막 상태 카드·결과 문구·
미해결 이유 표기·열 개 언어 문구를 포함해 통과했습니다. 켜기 본문에서 퇴역한 두 관문과
외부 규칙 비활성화 호출이 되살아나면 실패하는 소스 회귀시험을 추가했고, 제3자 고지는 다시
생성했습니다. 설계를 보안·이관·계약 세 관점에서 독립 반증한 검토와 코드 반증 리뷰를 받아,
보호막을 한 건에서 다섯 건으로 나누고 끄기·원복의 보호막 제거 관문, 0.3.4 활성 계약 승격 경로,
인증 우회 규칙 판정, 복구 카드 진입점, 진단 코드 유지를 반영했습니다. 개발 결과와 최종 소스의 필수 검증은 별도로 기록하며, 과거 버전의 통과
수치나 중간 소스의 결과를 새 설치본 증거로 재사용하지 않습니다.

이 변경일기 작성 뒤 확정한 소스에서 Windows x64·i686 시험, 양쪽 Clippy, 정적 검사·보안 감사·
설치본 빌드 등 필수 14단계를 실행하고, 두 업데이트 서명과 정확한 아홉 자산을 확인한 뒤
게시합니다. 실제 결과와 고정 소스·설치본 해시는 배포 마감 기록에서 별도로 확인합니다.
실제 설치·업그레이드·제거, 실제 PC의 SSH 켜기·끄기·원복, 두 물리 PC의 로그인·SFTP·공유,
재부팅 후 재접속, 다섯 규칙의 실제 등록과 차단 효과는 `NOT_RUN`입니다.
제보된 PC의 실제 해결과 전체 Windows 호환성은 실기 확인 전까지 주장하지 않습니다.
최종 소스 검증·두 업데이트 서명·아홉 공개 자산·공개 재다운로드는 각각 해당 절차의 실제
증거로 확인합니다. 이 문서는 그 절차의 완료나 새 버전의 게시 자체를 증명하지 않습니다.

이번 패치는 물리 LAN 전용 SSH 계약을 유지합니다. 켜기가 외부 규칙을 끄지 않으므로 일반
규칙 변경 상한 4개는 켜기 관문에서 빠졌습니다. VPN·가상 어댑터 경유 SSH와 인터넷 포트
포워딩은 지원하지 않습니다. VPN 이름 예외, 장부 스키마(V4/V5) 폐지, 그룹 정책 배포 우회 규칙
판정, 완전 원복의 외부 규칙 기록 포기 동의 경로, 제거기의 보호막 선택은 완료한 것으로 표시하지 않으며, 퇴역한 사전 점검 코드는 회귀시험 참조용으로만 남아
있습니다.

`0.1.2 <= 버전 <= 0.4.9`는 무료 Early Access이며 다음 제한을 유지합니다.

- Windows Authenticode 게시자 서명이 없습니다. Windows가 실행을 막을 수 있습니다.
- Windows 10/11 Home·Pro 전체 실기 검증이 완료되지 않았습니다.
- 실제 두 PC의 SSH/SFTP 실기 검증이 완료되지 않았습니다.
- 외부 법률 검토가 완료되지 않았습니다.
- 독립 공급망 검토가 완료되지 않았습니다.

기존 키의 Tauri 업데이트 서명, 별도 Minisign 서명과 SHA-256은 계속 필수지만
Windows 게시자 신원을 대신하지 않습니다. 보안 프로그램을 끄지 마세요.

복구 가능한 시험 PC에서 최신 백업과 보안 제품을 유지하며 확인하세요. 실패가 반복되면
앱·설정·복구 기록을 보존하고 진단 코드를 확인하세요. 방화벽 초기화, 기록 삭제나 보안
해제로 우회하지 마세요. 모든 환경에서의 무결함·접속 성공·보안 보장을 주장하지 않습니다.
