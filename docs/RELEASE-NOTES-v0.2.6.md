# PCssak Gongyu 0.2.6 — 무료 Early Access

이번 업데이트는 “SSH를 껐다가 다시 켰는데, 왜 첫 준비 단계에서 또 멈출까?”라는 제보에서
시작했습니다. 이미 잘 쓰던 SSH와 설정을 그대로 두고 켜기·끄기만 하고 싶다는 말씀도 함께
살폈습니다. 그래서 0.2.6에서는 새 기능을 늘리기보다 **예전 기록을 정확히 읽고, 바꾸기 전에
기록하고, 실패하면 돌아갈 자리를 잃지 않는 일**에 집중했습니다.

아래에는 이번에 바꾼 내용과 그 이유를 차근차근 남깁니다. 코드에서 확인한 결함을 고쳤다는
사실과 제보하신 PC에서 문제가 해결됐다는 사실은 다릅니다. 2번 PC의 정확한 실패 로그와
새 버전 실제 접속 결과는 아직 확인하지 못했습니다. 이 차이도 끝까지 분명히 기록하겠습니다.

## 1. 예전 방화벽 기록을 새 기록으로 착각하던 길을 고쳤습니다

이전 버전에서 남긴 복구 기록은 버전에 따라 모양이 다릅니다. 그런데 SSH를 켜기 전에
검사하는 일부 경로가 V1~V3 방화벽 기록을 V4로만 해석하던 문제가 있었습니다. 기록이
남아 있다는 이유로 실패하는 상황을 줄이려면, 기록을 지우는 대신 해당 형식을 제대로 읽어야 합니다.

구형 기록은 해당 형식으로 검증하며, 실제 적용과 같은 계획으로 규칙 개수를 계산합니다.
임시 변경 상한 4개는 유지합니다. 이름이 같다고 안전한 규칙으로 넘기거나, 상한을 늘려
한꺼번에 끄는 방식으로 해결하지 않습니다. 구형 기록을 이관할 때 원문과 이번 호출 전의
검증된 상태를 보존하고, 대응이 불명확하면 변경을 시작하지 않습니다.

이후 단계가 실패해도 원래 기록과 이번 호출 전 상태를 복구할 수 있도록 했습니다.
“복구를 시도했다”와 “복구를 확인했다”를 구분하며, 확인하지 못한 기록을 성공으로 지우지 않습니다.
기존 사용자 SSH와 외부 방화벽 규칙을 일괄 초기화하지 않습니다.

## 2. 기록을 옮기던 중 앱이 멈췄을 때도 돌아갈 길을 남깁니다

첫 수정 뒤에는 그 과정 자체가 중간에 끊기는 경우도 다시 살폈습니다. 구형 V1/V2 기록으로
원래 방화벽 범위를 복구하던 중 앱이 종료되면, 남아 있는 V4 준비·복구 기록을 더 새로운
형식으로 강제 이관하려다 다음 켜기가 막히는 경로도 있었습니다.

이 경우는 호환 복구 경로에서 이어 읽도록 보완합니다. 처음의 기록 원문과 원래 정책은
그대로 보존하고, **이번 재시도 직전의 검증된 상태**는 별도로 기록합니다. 재시도가 실패하면
그 직전 상태로 돌아가야 하므로, 맨 처음 상태와 매번의 재시작 기준을 하나로 섞지 않습니다.

같은 이름의 중복 규칙, 알 수 없는 정책 변경, 기존 관리 건수를 포함한 상한 초과는 계속
거부합니다. 남은 기록이 있다는 이유만으로 임의의 현재 상태를 복구 대상으로 받아들이지 않습니다.
중단된 형식의 재개와 상위 단계 실패 후 원문 복구는 회귀 범위에도 포함합니다.

## 3. 설정을 바꾸기 전에 기록부터 확실히 남깁니다

되돌릴 기록이 불확실한데 다음 설정부터 바꾸면, 처음 문제보다 복구가 더 어려워질 수 있습니다.
자동 설정의 서비스·레지스트리 변경은 원래 상태 기록과 재조회가 성공한 뒤 진행합니다.
값이 없는 상태와 읽기 실패를 구분하고, 읽을 수 없는 복구 기록을 성공으로 지우지 않습니다.

기록을 저장하지 못하거나 저장한 내용을 다시 확인할 수 없으면 다음 변경을 중지합니다.
기존 중단 작업의 복구 원본도 새 작업의 편의를 위해 덮어쓰지 않습니다. 읽기 실패를
“원래 값이 없었다”로 처리하거나, 기록 실패 뒤에 계속 진행하는 일을 막는 보완입니다.

네트워크 기록도 같은 원칙으로 맞췄습니다. 새로운 공용 네트워크 전환은 연결 이름 대신
GUID를 기록하고 저장·재조회를 완료한 뒤 적용합니다. 이름이 같다는 이유로 다른 네트워크를
되돌리지 않도록 하기 위해서입니다. 구형 이름 기반 기록은 추정 이관하거나 삭제하지 않습니다.
기존의 신뢰 동의와 정확한 대상 확인은 그대로 필요합니다.

## 4. 업데이트를 지나도 이 PC가 겪은 일을 조금 더 기억합니다

마지막 작업 한 건만 남으면, 업데이트 전에는 무엇을 했는지 다시 살피기 어려웠습니다.
이번에는 작업 기록에 이전 종료 이력을 최대 32건·128KiB 범위로 보존합니다.
기존의 최근 종료 기록 1건과 현재 복구 상태는 별도로 유지합니다. 여기서 종료 이력은
성공한 작업만 뜻하지 않으며, 저장된 작업 결과를 함께 확인하는 참고 기록입니다.

작업 식별자·종류·앱 버전·시간·단계·결과·복구 기원을 다음 버전에서도 읽을 수 있게 합니다.
이력은 오래된 것부터 제한하며, 중복된 종료 처리가 같은 사건을 계속 쌓지 않도록 합니다.
기존 기록에 새 이력 항목이 없어도 읽을 수 있고, 기존 기록 읽기만으로 파일을 다시 쓰지 않습니다.

이 기록은 **해당 PC의 로컬 진단용**입니다. 과거 이력을 근거로 현재 PC가 안전하거나 이미
복구되었다고 추정하지 않습니다. Windows 복구 권한을 새로 부여하는 자료도 아닙니다.
현재 작업과 검증된 복구 기준은 기존 경로에서 따로 확인합니다.

기록은 해당 PC의 기존 로컬 저장소를 사용합니다. 전체 네트워크 패킷·사용자 문서·비밀번호·
SSH 개인키를 수집하거나 서버로 전송하는 기능을 추가하지 않습니다. 기록 개수·크기 제한,
이전 앱 버전 기록 읽기, 중복 호출, 저장 실패와 복구 원본 보존을 회귀 범위에 넣었습니다.

## 5. 같은 2%에서 멈춰도 어느 확인에서 멈췄는지 알려드립니다

첫 화면에 같은 진행률만 보이면 서로 다른 실패도 같은 문제처럼 느껴질 수 있습니다.
첫 단계 안에서 기존 SSH 확인, 이전 기록 확인, 방화벽 계획 확인을 구분해 표시합니다.
기록 형식·기록 읽기·보호 규칙·규칙 모호성의 진단 코드도 구분합니다.

한국어·영어·독일어·프랑스어·일본어·러시아어·튀르키예어·브라질 포르투갈어·중국어 간체·
번체의 10개 언어 안내를 함께 맞춥니다. 진단에는 원시 규칙명·개인 경로·계정 같은 민감한
상세를 넣지 않습니다. 원인이나 원복 성공을 확인하지 않은 상태에서 조직 정책 때문이거나
복구 완료라고 표시하지 않습니다. 실제 실패를 좁혀 볼 수 있도록 돕는 변경이며,
진행률 표시가 곧 접속 성공이나 처리 속도 향상을 뜻하지는 않습니다.

## 6. 잘 쓰던 SSH는 다시 설치하거나 우리 설정으로 덮지 않습니다

이미 설치된 검증된 OpenSSH에는 설치를 반복하지 않습니다. PCSSAK 관리 흔적이 없는
기존 설치는 서비스 시작·중지만 제공하고 방화벽·인증·키·포트·자동 시작 정책은 보존합니다.
기존 시작 유형이 사용 안 함이거나 설정·공유 계정 보호를 확인하지 못하면 몰래 설정을
고치는 대신 확인을 안내합니다.

외부에서 관리하는 SSH는 원래 네트워크 노출 범위를 유지합니다. 여기에 PCSSAK의 같은 LAN
전용 보호가 적용됐다고 표시하지 않습니다. 재부팅하면 원래 시작 정책이 적용되며,
서비스를 중지했다고 기존 인증 세션 전체가 종료됐다고 보증하지도 않습니다.

PCSSAK가 관리하던 SSH는 기존 끄기·다시 켜기·완전 원복 경로를 사용합니다.
PCSSAK 관리형 SSH는 동의한 신뢰 물리 LAN에만 허용합니다. 껐다 켜는 일과 기존 설정을
전부 초기화하는 일은 다르므로, 이번 호환성 수정을 위해 사용자 환경을 일괄 삭제하지 않습니다.

## 7. 0.2.5에서 넘어오는 설치도 빠뜨리지 않았습니다

이번 설치 파일은 `PCssak-Gongyu-0.2.6-Windows-x64-Setup.exe`입니다.
법률 정본과 업데이트 공개키는 유지합니다. 정상 법률 동의 기록이 있는 0.2.0~0.2.5는
다운로드·서명 검증·사용자 승인 후 앱 내 업데이트할 수 있습니다.

0.1.1~0.2.5는 먼저 제거하지 않습니다. 새 설치기가 기존 앱 파일을 보호 교체하고 설정·
법률 동의·공유·SSH 복구 기록을 보존합니다. 이번에는 0.2.5를 네 설치·중단 복구 분기에
추가하고, 버전 상수 누락과 이전 버전 허용 범위를 확인하는 회귀도 함께 준비합니다.
기존 앱을 지운 다음 새로 설치하는 방식으로 업데이트하지 않도록 한 변경입니다.

이전 전환 안내도 그대로 유효합니다.

- 0.1.9는 현행 법률 동의를 위해 공식 설치본을 직접 실행합니다.
- 0.1.8 이하는 앞서 고지한 업데이트 공개키 전환 때문에 공식 설치본을 한 번 직접 실행해야 합니다.
- 0.1.0은 별도 수동 제거 후 설치 대상입니다.
- 기록이 손상되었거나 새 동의가 필요하면 대화형 설치로 안내합니다.
  Windows 복구 기록을 임의로 삭제하지 마세요. 이미 앱을 제거한 경우에도 남은 정상 기록을
  지우거나 다른 버전의 파일을 섞어 복구하려 하지 마세요.

앱은 시작 시와 약 6시간 간격, 설정의 업데이트 확인으로 새 버전을 확인합니다.
다운로드가 끝나도 서명·해시 검증과 사용자 승인을 생략하지 않습니다.

## 8. 배포 설명도 매번 실제 변경을 따라가게 하겠습니다

제품 버전·설치기 호환 목록·보안 설명·공개 템플릿·버전별 MPL 원본 이름과 링크를
0.2.6에 맞춰 대조합니다. 법률 정본이나 기존 공개 자산을 임의로 고치는 작업은 포함하지 않습니다.
홈페이지에는 한영 상세와 추가 8언어 소개로 같은 변경 이유와 미확인 범위를 전달하고,
실제 공개 자산을 대조하기 전에는 새 다운로드 게이트를 켜지 않습니다.

앞으로도 릴리스마다 불편했던 점, 원인과 변경 이유, 바꾼 내용 전체, 실제 확인한 범위와
아직 확인하지 못한 범위를 이런 변경일기로 남기겠습니다. 구현·시험·설치·문구·번역·문서의
보완을 빠뜨리지 않고, 예상한 결과를 실제 결과처럼 쓰지 않겠습니다. 소스의 정본과 공개
릴리스의 노트가 서로 다른 이야기를 하지 않도록 같은 내용으로 관리합니다.

## 확인할 것과 아직 확인하지 못한 것

최종 동결 소스의 Windows 로컬 14단계, 같은 소스의 빌드와 두 업데이트 서명, 법률 정본·
MPL 원본·정확한 불변 9자산 검증을 공개 전에 결속합니다. 이전 형식·손상된 기록·중복 규칙·
기록 저장 실패·상위 단계 실패 복구·V4 중단 재개·이력 크기 제한·설치 중단 복구를 회귀
범위에 포함합니다. 구체적인 최종 시험 결과와 공개 상태는 별도 마감 기록에 남깁니다.
이 노트가 준비됐다는 사실만으로 최종 시험이나 실제 게시가 끝났다는 뜻은 아닙니다.

제보된 2번 PC의 실제 설치·복구·SSH/SFTP 접속은 아직 확인하지 못했습니다.
코드에서 확인한 호환성 결함의 수정과 해당 PC의 해결 완료를 구분합니다. 모든 PC에서의
SSH 접속 성공이나 성능 향상 수치를 보장하지 않습니다. 조직 정책, 설치 원본 부재, 포트 점유,
계정 인증 문제까지 자동 해결하는 기능이 아닙니다.

공개 설치본은 Windows x64 전용입니다. Windows 10/11 Home·Pro 전체 실기, 실제 두 PC의
SSH/SFTP·설치·제거·재부팅 지속성, 외부 법률 검토와 독립 공급망 검토는 미완료입니다.
배포 전에 확인된 한계를 정본 문구로도 남깁니다.

- Windows 10/11 Home·Pro 전체 실기 검증이 완료되지 않았습니다.
- 실제 두 PC의 SSH/SFTP 실기 검증이 완료되지 않았습니다.
- 외부 법률 검토가 완료되지 않았습니다.
- 독립 공급망 검토가 완료되지 않았습니다.

Windows Authenticode 게시자 서명이 없습니다. Tauri 업데이트 서명·독립 Minisign 서명·
