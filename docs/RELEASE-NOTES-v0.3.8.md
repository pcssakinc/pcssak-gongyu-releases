# PCssak Gongyu 0.3.8 — Free Early Access 변경일기

**첫 0.3.8 후보는 실제 PC에서 장시간 대기와 창 닫기 차단이 재현되어 부적합으로 판단했습니다.
이번 수정판은 그 실패 기록과 회사 후속 구현을 다시 검토하고, 복구는 끝났는데 작업 기록이
남아 막히는 연결 문제까지 보완했습니다.** 실제 PC에서의 후속 설치·켜기·끄기·재켜기·재부팅
연속 실기는 **NOT_RUN**입니다. 자동 회귀와 공개 자산 검증을 제보 PC의 해결로 바꾸어 설명하지 않습니다.

「업데이트해도 이전 방화벽 기록 복구에서 계속 막힙니다.」 0.3.7에서도 같은 제보가 이어져
이번에는 저장된 원래 대상과 현재 Windows가 돌려주는 대상을 직접 대조했습니다. 앞선
0.3.5~0.3.7의 LAN 보호막·부재 기록 보관·중단 작업 연결은 유지하면서, 그 전에 멈추던 구형
복구 기록의 호환과 한 버튼 준비 동선을 보완했습니다.

## 1. 이름이 같은 규칙을 예전 규칙으로 바꿔치기하지 않습니다

실제 PC에서는 과거 기록에 보존 대상으로 남은 규칙 일부의 정확한 ID가 사라졌습니다.
현재 같은 이름으로 보이는 규칙은 다른 ID였고, 다른 한 대상은 여전히 존재하여 원래
활성 상태를 되돌릴 의무가 남아 있었습니다. 이름이나 VPN 제품명만 제외하는 방식으로는
이 두 경우를 안전하게 나눌 수 없습니다.

이제 원래 승인된 실제 복구 대상과 단순 관측 후보를 나눠 비교합니다. 보존 대상의 옛 ID가
정확 조회와 전체 ID 목록 모두에서 없음을 확인한 경우에만 새 인계 기록으로 원래 ID를 V5
보관 절차에 넘깁니다. 기존 승인 계획·승인 해시·완료 목록·원본 장부는 유지합니다.

새 이름 대응 규칙은 복구 대상으로 편입하지 않습니다. 살아 있는 대상의 원래 활성값과
당시 기준선은 그대로 보존합니다. 대상 정책 변경·읽기 실패·옛 ID의 재등장·실제 패키지 대상
변경은 계속 중단 사유이며, 없어졌다고 추정해서 원복 성공으로 처리하지 않습니다.

인계 계약은 적용 전에 보호 저장소에 먼저 기록하고 재개·장부 교체·완료 때 같은 출력과
원문을 다시 검증합니다. 이미 과거 방식으로 장부 교체를 확정한 기록은 자동 전환하지 않습니다.
새 인계 기록(스키마 3)은 구버전이 해석할 수 없으므로 적용 후에는 같은 수정 계열 앱으로 재개해야 합니다.
기록 삭제나 옛 실행 파일 강제 복귀로 우회하지 마세요.

이 비교 개선은 이미 저장된 구형 복구의 재개에 적용됩니다. 기록을 처음 만드는 미리보기와
최초 적용 사이에 환경이 달라지면 승인 계획이 만료될 수 있어, 대상을 다시 확인해야 합니다.

## 2. 평상시 켜기·끄기를 과거 복구와 분리합니다

사용자의 목표는 간단합니다. SSH가 없으면 설치하고 켜며, 설치돼 있으면 다시 설치하지 않고
켜고 끕니다. 켜면 서비스가 자동 시작하고, 끄면 서비스가 중지·비활성화되어 재부팅 뒤에도
꺼져 있어야 합니다. 기존 사용자 설치도 주 버튼에서는 이 동작을 적용하도록 구현했습니다.
기존 설치 소유권·설정·키와 최초 서비스 상태는 보존하며, 끄기는 OpenSSH 제거가 아닙니다.

첫 후보의 주 버튼은 중단된 구형 방화벽 복구를 먼저 재개하면서 긴 전체 조회를 반복했습니다.
이 연결을 분리했습니다. 독립된 구형 복구의 승인 원문과 진행 기록을 엄격히 확인해 별도
보존하고, 우리 SSH 규칙과 겹치지 않는 경우 정상 켜기·끄기로 진행하도록 구성했습니다. 과거
복구를 완료 처리하거나 원문을 삭제하지 않으며, 명시적인 복구 기능은 상세에 남깁니다.

이번 분리의 적용 범위는 SSH 서비스와 현행 SSH 설정 저장 키가 이미 있는 독립 구형 복구입니다.
옛 저장 키만 있는 환경이나 SSH 미설치와 미완료 구형 복구가 함께 남은 환경은 자동 분리하지
않습니다. 미완료 기록이 없는 일반 신규 설치는 기존 설치 경로를 유지합니다. 아직 실제 PC에서
이 분리 동작을 시험하지 않았으므로 모든 환경에서 해결됐다고 안내하지 않습니다.

정확 ID 복구가 미완료이거나 보호 기록이 없고 손상된 경우, 현재 관리 대상과 겹치는 경우도
분리하지 않습니다. 이 예외는 주 버튼의 켜기·끄기에만 적용하며, 공유 복구·완전 원복·제거의
미완료 기록 확인을 없애지 않습니다. 분리 조건을 충족하지 못하면 자동 전체 복구를 반복하지 않습니다.

보류 원본은 작업 저널 버전 2부터 별도로 저장합니다. 이번 마감 보완은 원래 작업 ID와 승인
계획·완료 증거를 묶는 작업 저널 버전 3을 추가했습니다. 기존 버전 1·2는 읽을 수 있지만 새
기록을 쓴 뒤에는 낮은 버전으로 되돌리지 않습니다. 이는 앞서 설명한 복구 인계 기록 스키마 3과
별개의 호환 제한입니다. 구버전은 이 작업 저널을
읽고 재개할 수 없으므로 같은 수정 계열 앱을 사용해야 합니다. 기록 삭제나 구버전 복귀로
차단을 우회하지 마세요.

복구 기록과 작업 완료 기록을 저장하는 사이에 앱이 종료되면 실제 복구는 끝났는데 남은 작업
기록 때문에 다시 막힐 수 있었습니다. 상세 복구에서 같은 작업 ID·승인 계획·현재의 정확한
대상·보관 원문을 확인한 뒤 마감을 재시도하도록 연결했습니다. 내부 완료와 마지막 공개 표식의
미마감도 구분합니다. 저장 실패나 중지 뒤에는 같은 작업과 증거를 보존하며, 다른 작업이나
새 승인으로 바꿔 성공 처리하지 않습니다.

옛 버전 기록에는 이러한 결속이 없을 수 있습니다. 그 경우 별도 확인을 받고 현재 대상과
보관 기록을 다시 검증한 뒤 **수동 확인 완료**로 정리합니다. 이를 과거 복구 성공으로 표시하지
않으며, 재시도에서도 수동 확인이라는 결과를 유지합니다. SSH 켜기 주 버튼이 다른 독립 작업의
마감을 자동 승인하거나 남은 SSH 부모 작업을 대신 완료하지 않습니다.

중단된 SSH 설치·켜기·끄기·완전 원복 자체를 단순 과거 기록으로 분리하지 않습니다. 같은
부모 작업의 ID와 종류를 확인하고 재개하며, 다른 작업으로 바뀌거나 사용자가 취소·앱 잠금을
하면 자동 진행하지 않습니다. 관리자 권한과 정확히 식별된 Public 물리 LAN의 신뢰 동의는
계속 필요합니다. 판독 실패나 보존 조건 불일치를 성공으로 처리하지 않습니다.

긴 설명은 상세 안내로 접고, 한 번의 클릭부터 총 경과 시간을 유지합니다. 끝난 하위 조회의
마지막 문구가 계속 작업 중인 것처럼 남지 않도록 실제 완료 상태도 구분합니다. 원본 보관과 현재 LAN
안전 상태는 별도로 판단합니다. 실제 Windows 규칙 복구가 안 된 항목을 보호 보관했다는 이유로
완전 원복까지 성공했다고 표시하지 않습니다.

## 3. 느린 조회의 최종 응답을 버리지 않습니다

실제 재시험에서 첫 복구 미리보기는 약 197초에 끝났고, 그중 약 194초가 465회의 네이티브
정책 조회에 쓰였습니다. Count 하나가 멈췄다는 증거는 없었습니다. 같은 관측 안에서 이미
읽은 정책만 재사용하고, 정확한 변경 후 검증이 끝났는데도 반복하던 판독을 줄였습니다.
정상 LAN 보호막과 소유 허용 규칙을 엄격히 확인할 수 있으면 불필요한 패키지 정책 조회도
생략합니다. 적용 전과 최종 검증에 오래된 관측 결과를 재사용하지 않습니다.

앱 시작 자동 조회와 주 버튼이 각각 상태 조회를 보내면 두 번째 요청이 「이전 조회 진행 중」으로
끝나는 경합이 있었습니다. 이제 동일 세대의 진행 중인 조회를 공유하여 실제 응답 뒤 같은 준비
동선으로 이어갑니다. 변경 작업이나 앱 잠금 이전의 오래된 응답은 최신 상태로 재사용하지 않습니다.

이전에는 화면 응답 제한 시간이 지나면 실제 Windows 조회가 계속 실행 중인데도 호출 응답만
끝날 수 있었습니다. 상태·물리망 사전 조회는 기존 시간을 지연 진단 시점으로 사용하고 같은
실제 작업의 최종 응답을 기다립니다. 반복 호출로 새 작업을 쌓거나 경과 시간을 가짜 진행률로
바꾸지 않습니다. 준비 단계의 명시 취소는 대기를 끝내고 후속 설정 변경을 막습니다.

완료한 켜기·끄기·원복·기존 서비스 제어 뒤의 표시용 상태 조회는 작업 완료와 분리합니다.
화면 조회만 느리다고 완료한 작업의 주 버튼까지 잠기지 않으며, 다음 준비에서는 진행 중인
조회의 유효한 결과나 새 조회로 상태를 확인합니다. 보호 복구의 필수 완료 확인은 유지합니다.

복구 적용 중 중지와 창 닫기는 안전 중지를 요청하고 실제 워커가 끝난 뒤 처리하도록
구현했습니다. 한 항목의 복원·재검증·완료 기록 도중에는 중단하지 않으며, 중지 완료를 원복
완료로 표시하지 않습니다. 이미 실행 중인 Windows 호출은 반환을 기다려야 합니다.

이 변경은 멈춘 Windows 호출을 강제 종료하는 기능이나 조회 속도 향상 보장이 아닙니다.
실제 호출이 영구 정지하는 경우의 종료 가능한 읽기 전용 보조 프로세스는 별도 검토 대상입니다.

## 설치와 업데이트

0.3.7에서 0.3.8로 보호 교체하는 설치기 분기와 중단 후 원본 보존 회귀 검사를 추가했습니다.
실제 설치 패키지의 교체·제거 시험은 아직 미실행입니다. 먼저 앱을 제거하거나 설정·공유·
SSH·복구 기록을 지우지 마세요.
업데이트 자체가 방화벽 복구를 완료하거나 SSH를 자동으로 켜는 것은 아닙니다.

- 설치 파일은 `PCssak-Gongyu-0.3.8-Windows-x64-Setup.exe`입니다.
- 0.1.0에는 앱 내 업데이트가 없으므로 공식 설치본을 한 번 수동 설치해야 합니다.
- 법률 정본과 업데이트 공개키를 바꾸지 않습니다. 정상 법률 동의 기록이 남은 0.3.7 사용자는 앱에서 새 버전을 확인하고 다운로드·서명 검증·사용자 승인 후 업데이트할 수 있습니다.
- 해당 버전 MPL 원본 이름: `PCssak-Gongyu-0.3.8-MPL-Sources.zip`
- 공개 대상: Windows x64. Windows x86 설치본은 별도 실기 증거 전에는 공개하지 않습니다.
- 법률 정본·업데이트 공개키는 유지합니다. 개인키는 저장소나 릴리스 자산에 올리지 않습니다.
- 정상 법률 동의 기록이 있는 공개 0.2.0~0.2.8·0.3.2~0.3.7과 비공개 0.2.9·0.3.0·0.3.1은
  실제 공개 후 다운로드·서명 검증·사용자 승인형 업데이트 계약을 따릅니다.
- 0.1.1~0.3.7은 설치기 코드의 보호 교체 대상이며 실제 PC의 교체 시험은 별도입니다. 0.1.0만 별도 제거 후
  설치합니다. 0.1.9는 현행 법률 문서의 대화형 확인, 0.1.8 이하는 이전 공개키 전환에 따른
  수동 설치가 필요합니다. 서명 오류를 우회하지 마세요.

앱 내 업데이트가 남은 중단 기록으로 차단되면 검증·공개된 공식 설치본의 보호 교체 경로를
사용합니다. 새 기록을 구버전으로 억지로 읽거나 원본 장부를 지우지 않습니다. 이전 불변
릴리스의 태그·자산·노트는 바꾸지 않습니다.

새 안내와 중지 상태는 지원 언어에도 반영했습니다. 설치 안내·보안 설명·자산 계약·의존성
고지의 제품 버전과 MPL 원본 파일명을 함께 맞췄으며, 의존성 패키지를 갱신한 변경은 아닙니다.

## 5. 확인한 결과와 남은 시험을 구분합니다

이번 개발 과정에서는 실제 PC의 옛 ID 부재와 살아 있는 원복 의무를 읽기 전용으로 확인했고,
인계 미리보기의 원문 보존도 확인했습니다. 이후 기존 설치 경로에 0.3.7 개발 실행 파일을
교체했지만 이는 새 설치 패키지 시험이 아닙니다. 수동 복구 적용 시도는 시험 도우미의 일반
장부 판독이 미완료 복구를 거부하여 생산 적용 전에 실패했습니다. 도우미를 전용 보호 저장소
판독으로 좁히고 승인 해시·원문·레지스트리 결속과 판독 전후 불변 검사를 유지했습니다.

이후 0.3.8 후보의 사용자 시험에서도 장시간 조회와 창 닫기 차단이 재현됐습니다. 일부 외부
규칙 변경 후 검증 로그가 있어 전체 읽기 전용 시험으로 집계하지 않습니다. 사용자 요청으로
앱만 종료했고 서비스와 보호 기록을 초기화하지 않았습니다. 최종 복구·SSH 전환 성공은
아직 미확인입니다. 후속 소스의 자동 시험과 실제 PC 결과를 별도로 기록합니다.

후속 후보의 실제 설치·업그레이드·제거·SSH 켜기/끄기·재부팅·두 PC 로그인/SFTP·패킷 차단
실기는 **NOT_RUN**입니다. 이전 후보에서 일부 동작한 사실을 후속 설치본의 성공으로 옮기지 않습니다.

개발 회귀 검증에는 중단 후 재개, 원문·해시 보존, 새 동명이인 변경 0회, 살아 있는 대상의
원복 의무, 영속화 실패, 옛 ID 재등장, 변경된 정책 거부를 포함합니다. 화면에서는 한 버튼
연속 흐름, 늦은 응답 공유, 취소·앱 잠금·중복 클릭과 변경 완료 뒤 표시 조회 지연을 검사합니다.
개발 중 실제로 실행한 코드·화면 회귀와 양쪽 아키텍처 검사는 해당 소스의 결과로 보존합니다.
이를 추가 수정 뒤 최종 소스의 통과로 재사용하지 않으며, 아직 실행하지 않은 시험 수치를
미리 적지 않습니다. 회사에서 중단한 전체 정적 검사도 그대로 실패·미완결 기록으로 보존합니다.

최종 검토에서 준비 취소 뒤 늦은 응답이 화면 상태를 덮는 문제와 접힌 상세 안의 복구 버튼이
이동 후에도 보이지 않는 문제를 재현하고 수정했습니다. 응답의 현재성을 전역 안내 전에 확인하고
상세를 펼친 뒤 이동합니다. 보호 복구와 작업 기록의 마감 연결도 보완했습니다. 수정 뒤 화면
606개와 SSH 정적 계약의 양성 1개·거부 사례 50개가 통과했습니다. Rust는 x64와 i686에서
각각 1,103개가 통과했고 승인된 실기 전용 26개는 실행하지 않았습니다. 양쪽 Clippy도 경고를
오류로 처리하는 검사에 통과했습니다. 이는 개발 회귀 결과이며 최종 설치본이나 실제 PC의
성공을 대신하지 않습니다. 최종 14단계는 깨끗한 소스와 별도 실행 증거로 결속합니다.

GitHub Actions 시간 대신 승인된 Windows 로컬 최종 14단계를 사용하되, 최종 소스·도구·
명령·종료 코드·원문 로그 해시를 결속해야 합니다. 개발 시험은 최종 검증·설치본·기존 키의
두 업데이트 서명·정확한 아홉 자산·공개 판독을 대신하지 않습니다. 새 설치본 설치·업그레이드·
제거, 재부팅, 두 물리 PC의 SSH 로그인·SFTP·패킷 차단과 Windows 전체 행렬도 별도입니다.

`0.1.2 <= 버전 <= 0.4.9`는 무료 Early Access이며 다음 제한을 유지합니다.

- Windows Authenticode 게시자 서명이 없습니다. Windows가 실행을 막을 수 있습니다.
- Windows 10/11 Home·Pro 전체 실기 검증이 완료되지 않았습니다.
- 실제 두 PC의 SSH/SFTP 실기 검증이 완료되지 않았습니다.
- 외부 법률 검토가 완료되지 않았습니다.
- 독립 공급망 검토가 완료되지 않았습니다.

기존 SSH 설치·설정·키를 보존하고 주 버튼은 서비스의 실행 및 재부팅 후 시작 상태를
관리합니다. 판독 실패를 안전으로 표시하지 않습니다. VPN 연결은 유지할 수 있지만 VPN 경유 SSH와 인터넷 포트 포워딩은 지원하지
않습니다. 신뢰한 물리 LAN의 제한된 경로만 허용합니다. Tauri 업데이트 서명, Minisign 서명과 SHA-256은
Windows 게시자 신원을 대신하지 않습니다. 보안 프로그램을 끄지 마세요. 최신 백업과 보안
제품을 유지하며 복구 가능한 시험 PC에서 확인하고, 실패하면 원본 기록과 진단을 보존하세요.
