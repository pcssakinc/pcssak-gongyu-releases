# PCssak Gongyu 0.2.8 — 무료 Early Access

이번 기록은 0.2.8의 원인 확인과 개발 회귀까지 이어 온 변경일기입니다. 최종 동결 소스의
14단계 검증·설치본·서명·공개 검증은 별도 마감 기록에 남기며, 아래에서는 확인한 변경과
아직 실제 PC에서 확인하지 못한 범위를 구분합니다.

“업데이트했는데도 SSH 켜기에서 방화벽 규칙 28개가 걸린다”는 제보를 다시 살펴봤습니다.
숫자가 많다고 모두 SSH 서버를 넓게 열어 두는 규칙은 아니었습니다. Microsoft Store나
Teams처럼 특정 패키지 앱에만 적용되는 규칙이 일반 SSH 충돌 후보에 섞일 수 있었습니다.
이번에는 그 앱 전용 범위를 더 정확하게 확인하는 데 집중합니다. 기존 SSH 설치를
다시 깔거나 방화벽 전체를 초기화하는 방향으로 문제를 덮지 않습니다.

## 1. 앱 전용 규칙이 일반 충돌로 섞이던 이유를 확인했습니다

Windows의 서로 다른 방화벽 조회 경로는 패키지 앱 정보를 같은 필드에 항상 보여 주지
않았습니다. COM과 CIM에서 패키지 SID가 비어 있어도 패키지 이름인 PFN이 남아 있을 수
있는데, 그 경우를 충분히 연결하지 못하면 앱 전용 규칙을 일반 규칙으로 셀 수 있었습니다.

이전 자료에는 PFN이 있는 규칙 25개와 일반 규칙 3개가 함께 있었습니다. 이번 제보에서도
28개로 표시된 목록에 Store·Teams 등의 앱 규칙이 섞인 점을 확인했습니다. 표시된
개수만으로 실제 변경 대상이 28개라고 판단하거나, 모든 제보가 같은 구성이었다고
단정하지 않습니다. 실제 적용 계획은 현재 규칙과 기존 복구 기록을 함께 확인해야 합니다.

## 2. 이름 대신 실제 규칙과 앱 범위를 맞추도록 보완합니다

0.2.8의 수정은 SID가 비었다는 이유만으로 앱 규칙을 일반 규칙으로 넘기지 않도록
PFN을 함께 대조하는 것입니다. 다만 PFN 문자열이 하나 보인다는 이유로 바로 제외하지는
않습니다. 실제 Windows 규칙 ID와 원문 정책, 패키지 조건이 정확히 대응되는 경우에만
그 앱에 한정된 규칙을 일반 SSH 충돌 후보에서 제외합니다.

같은 이름의 앱 규칙과 일반 규칙이 섞여 있어도 이름 전체를 예외 처리하지 않습니다.
각 실제 ID를 나누어 확인하고, 일반 규칙은 별도 후보로 남깁니다. 중복 ID·모호한 대응·
서로 다른 원문·조회 오류는 안전하다고 추정하지 않습니다. 앱 전용임을 확인할 수 없는
규칙을 조용히 건너뛰거나 조직 정책을 무시하는 기능은 추가하지 않습니다.

이미 패키지 SID로 앱 전용임을 확인한 규칙은 추가 PFN 원문 조회를 하지 않습니다.
PFN 확인 중 생긴 오류는 `SSH-FW/PACKAGE-FAMILY` 진단으로 구분하여, 기존의 다른
규칙 식별 오류나 설치 실패와 섞이지 않도록 합니다. 진단이 남으면 해당 확인 단계와
기존 복구 안내를 함께 살펴볼 수 있습니다.

## 3. 기존 복구 기록과 이미 설치한 SSH는 그대로 존중합니다

비교를 보완한다고 기존 복구 장부의 원문이나 정책 해시 형식을 다시 쓰지 않습니다.
원래 기록과 실제 규칙의 대응, 변경 전 기록 저장, 실패 시 복구·재조회 경계를 유지합니다.
같은 이름이 여러 개 있다는 이유로 복구 대상을 다른 규칙으로 바꾸지 않습니다.

이전에 패키지 규칙까지 잘못 포함해 저장한 장부는 이번 판별 수정만으로 자동 삭제하지
않습니다. 기존 장부의 원래 복구 경로로 실제 상태를 확인해야 하며, 복구를 확인할 수
없으면 기록을 보존하고 안내를 따릅니다. 새 계획에서 앱 전용 규칙을 제외하는 기능이
과거 장부까지 안전하게 정리했다고 뜻하지는 않습니다.

PCSSAK 밖에서 정상 설치한 SSH는 기존 설치·인증 설정·방화벽·자동 시작 유형을 유지하고
검증된 서비스 시작·중지만 요청합니다. 공유 관리 계정이 없는 수동 SSH의 첫 시작 전에
설정 파일이 아직 없을 수 있다는 0.2.7의 처리도 이어갑니다. 공유 관리 계정이 있으면
기존 접근 차단 보호와 시작 완료까지의 파일 보호를 확인하며, 사용 안 함 시작 정책을
임의로 변경하지 않습니다. PCSSAK 관리 흔적이나 중단 기록이 있으면 기존 관리·복구
경로를 사용합니다. 기존 외부 SSH의 노출 범위를 같은 LAN 보호로 바꿨다고 표시하지 않습니다.

구형 기록 V1~V3 호환과 이관 중 남은 V4 기록 재개, 최초 원문·재시도 직전 상태 구분,
네트워크 GUID, 로컬 종료 이력 최대 32건·128KiB도 유지합니다. 이력만으로 현재 상태나
복구 권한을 판단하지 않으며 미확인 복구를 완료로 지우지 않습니다.

## 4. 일반 규칙 네 개의 자동 처리 상한은 유지합니다

앱 전용 규칙을 정확히 분리하는 것과 안전 상한을 늘리는 것은 다른 일입니다.
실제 일반 충돌 규칙과 기존 복구 대상을 포함한 임시 변경 계획의 상한은 계속 4개입니다.
일반 규칙이 5개 이상 필요한 환경은 이번 수정 뒤에도 자동 처리할 수 없습니다.

그 경우에는 관리자와 해당 규칙의 필요성을 검토해야 합니다. 이름만 보고 규칙을
삭제하거나 모든 방화벽을 초기화하고, 보안 제품을 끄도록 안내하지 않습니다.
새로운 영구 차단 방식으로 전면 교체하는 릴리스도 아닙니다.

## 5. 같은 TCP 22 표현을 허용 범위에서도 같게 다룹니다

`22`, `22-22`, `22,22`는 숫자 포트 집합으로는 같은 한 포트를 뜻합니다. 비교용 정규화는
같다고 보는데 실제 허용 범위 판정은 다르다고 거부하던 경로를 확인했습니다. 먼저
`22-22` 입력이 실패하는 회귀를 확보하고, 허용 범위도 숫자 포트 집합으로 판단하도록
수정한 뒤 해당 회귀가 통과하는 것을 확인했습니다. 다른 포트를 포함한 구간·알 수 없는
동적 포트·잘못된 문법까지 허용한다는 뜻은 아닙니다. 이 표적 자동 시험을 제보 PC에서
SSH 접속까지 성공한 결과로 확대하지 않습니다.

## 6. 0.2.7에서의 업데이트도 기존 설정을 지키도록 연결했습니다

이번 설치본 이름은 `PCssak-Gongyu-0.2.8-Windows-x64-Setup.exe`입니다. 직전 0.2.7을
보호 업데이트·중단 복구·수동 교체·재설치 네 분기에 추가했습니다. 기존 버전 분기와
소유 파일 표식은 유지하고, 새 분기나 시험 상수가 빠지면 실패하도록 확인했습니다.
정상 교체뿐 아니라 부분 실패와 다음 설치 실행의 복구에서도 설정·공유·SSH 장부를
보존하는 회귀를 통과했습니다. 이 자동 시험은 실제 설치 실기를 대신하지 않습니다.

0.1.1~0.2.7은 먼저 제거하지 않습니다. 새 설치기가 기존 앱 파일을 보호 교체하고
사용자 설정·법률 동의·공유·SSH 복구 기록을 보존합니다. 구 제거기를 실행하지 않습니다.
정상 법률 동의 기록이 있는 0.2.0~0.2.7은 다운로드·서명 검증·사용자 승인 후 앱 내
업데이트할 수 있습니다. 법률 정본과 업데이트 공개키는 유지합니다.

- 0.1.9는 현행 법률 동의를 위해 공식 설치본을 직접 실행합니다.
- 0.1.8 이하는 앞서 고지한 업데이트 공개키 전환 때문에 공식 설치본을 한 번 직접 실행해야 합니다.
- 0.1.0은 별도 수동 제거 후 설치 대상입니다.
- 기록이 손상됐거나 새 동의가 필요하면 대화형 설치로 안내합니다. 남은 Windows 복구 기록을 임의로 삭제하지 마세요.

앱은 시작 시와 약 6시간 간격, 설정의 업데이트 확인으로 새 버전을 확인합니다.
다운로드가 끝나도 서명·해시 검증과 사용자 승인을 생략하지 않습니다.

## 설치와 앱 내 업데이트

- 설치 파일은 `PCssak-Gongyu-0.2.8-Windows-x64-Setup.exe`입니다.
- 법률 정본과 업데이트 공개키를 바꾸지 않습니다. 정상 법률 동의 기록이 남은 0.2.7 사용자는 앱에서 새 버전을 확인하고 다운로드·서명 검증·사용자 승인 후 업데이트할 수 있습니다.
- 0.1.0에는 앱 내 업데이트가 없으므로 공식 설치본을 한 번 수동 설치해야 합니다.

## 7. 설치본·설명서·공개 문서도 함께 맞춥니다

Cargo 제품 버전·잠금 항목·Tauri 버전, 한영 매뉴얼·README·보안 안내·공개 템플릿과
버전 고정 자산 이름·URL을 0.2.8에 맞췄습니다. 실제 NSIS 시험기의 이전 버전 상수 목록도
현재 보호 교체 목록과 맞춰 누락을 보완했습니다. 제품 버전 외 의존성 버전·법률 정본·
업데이트 키는 바꾸지 않습니다. 제3자 고지를 다시 생성했으며 326개 의존성 목록은
유지하고 제품 버전·잠금 파일 해시·MPL URL만 0.2.8에 맞췄습니다. 최종 동결 소스와
실제 MPL 원본·공개 자산의 결속 검증은 별도 출시 관문으로 이어갑니다.

과거 노트·업무일지·불변 공개 자산은 보존합니다. 이 변경일기의 비공개 정본과 공개
템플릿은 같은 바이트로 관리하고, 새 오류나 남은 제약이 확인되면 숨기지 않고 이어 적습니다.

## 확인한 범위와 아직 남은 확인

현재 개발 PC에서 PFN 규칙은 0개이므로 실제 PFN이 있는 Windows 환경을 재현한 검증은
NOT_RUN입니다. 개발 x64 전체 회귀는 869개 통과·0개 실패·13개 제외로 확인했습니다.
개발 x64 Clippy의 경고 오류 처리와 화면 회귀 374개도 통과했습니다.
제보 자료와 같은 패키지/일반 혼합 입력, 같은 이름의 서로 다른 규칙, 원문·ID·패키지
불일치와 상한 초과를 자동 회귀로 확인했습니다. 같은 이름의 PFN 규칙 25개와 일반
규칙 3개가 섞인 입력에서는 일반 규칙 3개만 임시 변경하고 앱 규칙 25개는 보존하며,
마지막 상태 재조회와 원래 상태 복구까지 확인했습니다. PFN 조건 및 Windows 원문의
`LUOwn`·`Platform`·`TTK` 같은 부가 필드를 포함한 회귀도 추가했습니다. 이 결과를
실제 제보 PC의 해결로 확대하지 않습니다.

설치기 순수 계약은 13,120사례와 후속 보존 계약을 통과했습니다. 검증된 NSIS 3.12로
실제 네 분기 1,340사례·시험 상수 누락 76사례를 확인했고, 경고를 오류로 처리한
컴파일도 통과했습니다. 제품 설치·레지스트리·서비스·방화벽 변경을 수행한 실기는 아닙니다.

최종 버전 동결 소스의 Windows 로컬 14단계, 같은 소스의 설치본 빌드와 두 업데이트
서명, 법률·MPL 원본·정확한 불변 9자산 및 공개 후 재다운로드 검증은 별도 마감 기록에
실제 결과를 남깁니다. 이 개발 회귀 기록만으로 최종 시험·서명·GitHub 또는 홈페이지 게시가
완료됐다는 뜻은 아닙니다. 제외된 시험을 통과로 세지 않습니다.

제보 PC를 포함한 실제 설치·제거·SSH 켜기·끄기·두 PC SSH/SFTP·재부팅 지속성은
미실행입니다. 공개 설치본은 Windows x64 전용이며, i686 코드 시험 통과가 x86 설치본
공개나 Windows 10/11 Home·Pro 전체 실기 통과를 뜻하지 않습니다. 모든 PC의 접속
성공, 인증·포트 점유·조직 정책 문제의 자동 해결을 보장하지 않습니다.

- Windows 10/11 Home·Pro 전체 실기 검증이 완료되지 않았습니다.
- 실제 두 PC의 SSH/SFTP 실기 검증이 완료되지 않았습니다.
- 외부 법률 검토가 완료되지 않았습니다.
- 독립 공급망 검토가 완료되지 않았습니다.

Windows Authenticode 게시자 서명이 없습니다. Tauri 업데이트 서명·독립 Minisign 서명·
SHA-256은 무결성을 검증하지만 Windows 게시자 신뢰를 대신하지 않습니다. Windows나
보안 제품이 실행을 막을 수 있습니다. 보안 프로그램을 끄지 마세요. 서명 오류도 우회하지 마세요.
해시나 서명이 다르면 중단하세요.
