# PCssak Gongyu 0.2.7 — 무료 Early Access

이번에는 “SSH를 켜려고 했는데 방화벽 확인에서 다시 멈춘다”는 불편에서 출발했습니다.
0.2.6에서 예전 복구 기록을 읽는 길을 보완했지만, Windows가 같은 규칙을 서로 다른
모양으로 보여 줄 때 두 관측을 연결하지 못하는 문제가 더 있었습니다. 0.2.7은 그 비교와
기존 SSH 상태 판별을 다듬어, 필요한 확인은 지키면서 불필요하게 막히는 길을 줄입니다.

제보 PC의 정확한 원시 로그는 아직 확보하지 못했습니다. 아래 내용은 코드에서 재현하고
고친 결함과 현재 개발 PC의 확인 결과입니다. 제보하신 PC에서 설치나 접속이 성공했다는
뜻으로 넓혀 말하지 않겠습니다.

## 1. 같은 규칙인데 다르게 보이던 값을 제대로 비교합니다

Windows 방화벽의 두 조회 경로는 같은 규칙도 다르게 표시할 수 있습니다. 경로의
구분자·대소문자가 다르거나, 같은 포트 목록의 순서와 구간 표현이 달라지는 경우입니다.
세 프로필을 모두 선택한 값과 전체 프로필 표기도 비교할 때 같은 범위로 다뤄야 합니다.

먼저 같은 포트 집합·실행 경로·프로필을 서로 다른 표현으로 만든 회귀시험을 넣었습니다.
수정 전에는 실제 켜기 계획에서 `native_com_candidate_mapping_count`로 실패했습니다.
이번에는 숫자 포트의 순서·중복·겹치는 구간을 정리하고 경로 구분자와 검증된 Windows
루트 별칭, 전체 프로필 표기를 통일하여 **비교할 값만** 맞춥니다.

원래 방화벽 규칙을 새 모양으로 고치거나 복구 기록의 해시를 다시 만드는 작업은 아닙니다.
변경·원복에는 계속 실제 Windows 규칙 식별자와 원본 정책 해시를 사용합니다. 다른
프로그램이나 실제로 다른 포트 집합을 같다고 받아들이지 않으며, 알 수 없는 변수·동적
포트 이름·잘못된 구간은 임의로 전체 허용으로 해석하지 않습니다.

## 2. 관리 주체를 알기 위해 모든 규칙을 훑지 않습니다

우리 프로그램이 관리하는 SSH인지 확인하는 데 다른 프로그램의 방화벽 규칙까지 모두
읽을 필요는 없었습니다. 관련 없는 규칙의 이름 하나를 읽지 못해도 기존 수동 SSH를
확인 불가로 분류할 수 있었고, 규칙이 많은 PC에서는 불필요한 조회가 늘어났습니다.

이제 관리 흔적의 존재 확인은 PCSSAK의 현재 허용·구형 허용·보호 차단 규칙 세 이름만
직접 조회합니다. 이미 관리 기록이 확정된 경우에는 그 분류를 위해 다시 조회하지 않습니다.
Windows의 정확한 부재 결과만 없음으로 인정하며 권한 부족이나 공급자 오류는 그대로
알립니다. 손상되거나 중복된 소유 규칙도 관리 흔적으로 보고, 실제 변경 직전의 엄격한
정책·중복 확인을 생략하지 않습니다.

## 3. 이미 설치한 수동 SSH의 첫 시작을 존중합니다

PCSSAK 밖에서 설치한 OpenSSH는 첫 서비스 시작 전에는 기본 설정 파일이 아직 없을 수
있습니다. 그런데 기존 서비스 시작에서도 무조건 그 파일을 요구하여, 설치는 정상인데
시작 요청을 보내지 못하는 길이 있었습니다.

공유 관리 계정이 없는 기존 수동 설치는 첫 시작 전 설정 파일이 없어도 시작을 요청할
수 있게 했습니다. OpenSSH의 기본 설정 생성 시점은
[Microsoft의 공식 설정 안내](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh-server-configuration)와
맞춥니다. PCSSAK이 설정 파일을 대신 만들거나 기존 인증·키·포트·방화벽을 덮어쓰지는 않습니다.

공유 관리 계정이 있다면 이야기가 다릅니다. 기존 SSH 접근 차단 설정을 확인하고 서비스
시작이 끝날 때까지 해당 파일의 보호를 유지합니다. 계정을 읽지 못한 일을 계정 없음으로
넘기지 않습니다. 중지나 바꿀 필요가 없는 요청에는 이 시작 전용 검사를 요구하지 않습니다.

시작 유형이 사용 안 함이면 임의로 수동이나 자동으로 바꾸지 않고 확인을 안내합니다.
기존 서비스형은 실행 상태만 다루며, 같은 LAN 전용 보호를 새로 적용했다고 표시하지
않습니다. PCSSAK의 관리·원복 기록이 남아 있으면 기존 관리·복구 경로를 계속 사용합니다.

## 4. 같은 식별 오류 안에서도 멈춘 지점을 구분합니다

`SSH-FW/IDENTITY-MATCH` 하나만으로는 예전 기록의 대응 문제인지, 현재 규칙의 관측
대응 문제인지 알기 어려웠습니다. 이제 구형 기록·현재 관측·패키지·대상·필터·저장소·
요청의 일곱 분류를 덧붙입니다. 화면에는 정해진 분류만 보여 주며, 원시 규칙명·계정·
개인 경로를 진단 코드에 섞지 않습니다. 분류를 알아냈다는 이유로 복구 완료나 특정
보안 제품이 원인이라고 단정하지 않습니다.

## 5. 같은 계획 안의 반복 해석을 줄였습니다

실제 ID로 새 변경 계획을 만들 때 규칙의 비교용 관측값과 패키지 조건을 한 번 준비해
재사용합니다. 이미 읽은 패키지 조건을 같은 계획에서 다시 해석하는 중복도 줄였습니다.
오래 남겨 둔 캐시로 현재 정책을 추측하는 방식은 아니며, 원본과 변경 직전 검증은 유지합니다.

현재 개발 PC의 읽기 전용 확인에서는 생산 계획에 고유 ID 3개가 잡혔고 4.602초가
걸렸습니다. 별도의 소유 흔적 조회는 17밀리초였으며 기존 전체 열거와 존재 결과가
같았습니다. 둘은 서로 다른 작업의 한 번 측정값이므로 개선 전후 속도 비율로 비교하지
않습니다. 모든 PC에서 같은 시간에 끝나거나 같은 폭으로 빨라진다고 보장하지 않습니다.
이 확인에서 서비스·설정·방화벽은 변경하지 않았습니다.

## 6. 이전 버전의 기록과 보호 경계는 이어갑니다

0.2.6에서 보완한 구형 방화벽 기록의 원문 보존, 중단 재개와 상위 실패 복구, 변경 전
기록·재조회, 네트워크 GUID 기록, 종료 이력 최대 32건·128KiB 보존을 유지합니다.
이력은 현재 안전 상태나 복구 권한을 추정하는 근거로 쓰지 않습니다.

실제 외부 규칙의 임시 변경 상한 4개도 유지합니다. 패키지 전용 규칙의 결속, 중복된
식별자, 손상된 원복 기록과 조회 실패를 무시하지 않습니다. 기존 외부 규칙을 일괄
초기화하거나 백신·조직 정책을 우회하는 기능을 추가하지 않았습니다. 이번 변경으로
새로운 영구 차단 방식으로 바뀐 것은 아니며 기존의 검증된 변경·원복 절차를 사용합니다.

## 7. 0.2.6에서의 업데이트도 기존 설정을 지킵니다

이번 설치본은 `PCssak-Gongyu-0.2.7-Windows-x64-Setup.exe`입니다. 0.2.6을 기존
설치·업데이트·중단 복구의 네 허용 분기에 추가하며, 분기가 빠지면 시험이 실패하도록
확인합니다. 정상 교체뿐 아니라 중간 실패와 다음 설치 실행의 복구에서도 이전 설정·
공유·SSH 장부를 보존하는 회귀를 추가했습니다. 자동 시험이 실제 설치 실기를 대신하지는 않습니다.

0.1.1~0.2.6은 먼저 제거하지 않습니다. 새 설치기가 기존 앱 파일을 보호 교체하고
사용자 설정·법률 동의·공유·SSH 복구 기록을 보존합니다. 구 제거기를 실행하지 않습니다.
정상 법률 동의 기록이 있는 0.2.0~0.2.6은 다운로드·서명 검증·사용자 승인 후 앱 내
업데이트할 수 있습니다. 법률 정본과 업데이트 공개키는 유지합니다.

- 0.1.9는 현행 법률 동의를 위해 공식 설치본을 직접 실행합니다.
- 0.1.8 이하는 앞서 고지한 업데이트 공개키 전환 때문에 공식 설치본을 한 번 직접 실행해야 합니다.
- 0.1.0은 별도 수동 제거 후 설치 대상입니다.
- 기록이 손상됐거나 새 동의가 필요하면 대화형 설치로 안내합니다. 남은 Windows 복구 기록을 임의로 삭제하지 마세요.

앱은 시작 시와 약 6시간 간격, 설정의 업데이트 확인으로 새 버전을 확인합니다.
다운로드가 끝나도 서명·해시 검증과 사용자 승인을 생략하지 않습니다.

## 설치와 앱 내 업데이트

- 설치 파일은 `PCssak-Gongyu-0.2.7-Windows-x64-Setup.exe`입니다.
- 법률 정본과 업데이트 공개키를 바꾸지 않습니다. 정상 법률 동의 기록이 남은 0.2.6 사용자는 앱에서 새 버전을 확인하고 다운로드·서명 검증·사용자 승인 후 업데이트할 수 있습니다.
- 0.1.0에는 앱 내 업데이트가 없으므로 공식 설치본을 한 번 수동 설치해야 합니다.

## 8. 설치본과 문서가 같은 버전을 말하게 맞춥니다

제품 버전·설치기 호환 목록·한영 매뉴얼·보안 설명·공개 템플릿을 0.2.7에 맞추고,
잠긴 의존성으로 제3자 고지를 다시 생성합니다. MPL 원본 묶음 이름과 링크도 이번
버전으로 고정합니다. 과거 노트·업무일지·불변 공개 자산은 보존합니다. 상세 노트의
소스 정본과 공개 템플릿은 같은 바이트로 관리합니다.

## 확인한 범위와 아직 남은 확인

버전 동결 전 개발 회귀에서 Rust x64·i686 각각 856개 통과·0개 실패·13개 제외를
확인했고 화면 사전검사도 통과했습니다. 수정 전 실패 재현을 보존하며, 서로 다른
프로그램·포트와 잘못된 입력을 구분하는 음성 회귀, 원본 정책 해시 보존, 관리 흔적
조회 실패, 수동 SSH 첫 시작과 공유 계정 보호, 진단 분류를 함께 확인했습니다.

최종 버전 동결 소스의 Windows 로컬 14단계, 같은 소스의 설치본 빌드와 두 업데이트
서명, 법률·MPL 원본·정확한 불변 9자산 및 공개 후 재다운로드 검증은 별도 마감 기록에
실제 결과를 남깁니다. 이 노트 준비만으로 최종 시험·서명·GitHub 또는 홈페이지 게시가
완료됐다는 뜻은 아닙니다. 제외된 시험을 통과로 세지 않습니다.

제보 PC를 포함한 실제 설치·제거·SSH 켜기·끄기·두 PC SSH/SFTP·재부팅 지속성은
미실행입니다. 공개 설치본은 Windows x64 전용이며, i686 코드 시험 통과가 x86 설치본
공개나 Windows 10/11 Home·Pro 전체 실기 통과를 뜻하지 않습니다. 모든 PC의 접속
성공, 인증·포트 점유·조직 정책 문제의 자동 해결을 보장하지 않습니다.

- Windows 10/11 Home·Pro 전체 실기 검증이 완료되지 않았습니다.
- 실제 두 PC의 SSH/SFTP 실기 검증이 완료되지 않았습니다.
- 외부 법률 검토가 완료되지 않았습니다.
- 독립 공급망 검토가 완료되지 않았습니다.

Windows Authenticode 게시자 서명이 없습니다. Tauri 업데이트 서명·독립 Minisign 서명·
SHA-256은 무결성을 검증하지만 Windows 게시자 신뢰를 대신하지 않습니다. Windows나
보안 제품이 실행을 막을 수 있습니다. 보안 프로그램을 끄지 마세요. 서명 오류도 우회하지 마세요.
해시나 서명이 다르면 중단하세요.

관리자 승인으로 `0.1.2 <= 버전 <= 0.4.9`는 무료 공개 Early Access로 제공합니다.
복구 가능한 시험 PC에서 최신 백업과 함께 사용하세요. 앞으로도 실제로 고친 부분과
아직 확인을 기다리는 부분을 나누어 기록하겠습니다.
