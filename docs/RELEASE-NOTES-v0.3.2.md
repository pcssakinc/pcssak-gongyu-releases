# PCssak Gongyu 0.3.2 — 복구가 어디까지 진행됐는지 함께 확인하는 변경일기

## 무료 Early Access — 공개 0.2.8 이후의 변경을 함께 담습니다

0.3.1을 직접 시험했을 때 「이전 방화벽 기록 복구」가 결과 조회 오류로 멈췄습니다.
적용 중에는 진행 표시도 사라져, 기다려야 하는지 다시 눌러야 하는지 알기 어려웠습니다.
이번 0.3.2는 그 실패를 출발점으로 복구 결과 판독과 화면 안내를 함께 개선했습니다.
새 경로의 개발 회귀는 통과했으며 최종 소스 14단계와 공개 자산 검증은 별도 마감 기록으로
확인합니다. 문서·버전 변경이나 자동 회귀만으로 실제 PC의 복구 성공을 뜻하지 않습니다.

이번 업데이트의 직전 공개판은 **0.2.8**입니다. **0.2.9·0.3.0·0.3.1은 비공개 시험본**이었으며,
이번 변경일기에는 그동안의 수정도 함께 담습니다. 중간 버전을 공개했다고 표시하거나
당시의 자동 검사 결과를 0.3.2의 성공 근거로 옮기지 않습니다. 기존 불변 릴리스·태그·
자산과 업데이트 공개키를 유지합니다.

## 1. 복구 결과의 ‘0’이 무엇인지 정확히 구분합니다

실제 0.3.1 복구는 관리자 실행 뒤 `native_method_output; hresult=0x00000000`으로
중단됐습니다. 사용 중인 WMI 바인딩은 실패가 아닌 상태 코드를 받은 뒤에도 결과 객체가
없으면 인터페이스 변환 오류를 만들 수 있습니다. 그 변환 오류의 코드 0만 남으면 원래
Windows 응답이 정상 완료였는지, 아직 결과를 기다리는 상태였는지 구분할 수 없습니다.
따라서 코드가 0이라는 이유로 오류를 무시하거나 복구 성공으로 간주하지 않습니다.

원래 HRESULT, 결과 객체 존재 여부, 메서드 반환값과 실제 규칙 상태를 나누어 확인하도록
보완했습니다. 메서드 완료를 확인한 뒤 같은 결과 핸들만 최대 5회 조회합니다. 완료 여부가 불명확하면 보호 대기를 유지합니다. 결과를
확인하지 못했다고 같은 변경 명령을 자동으로 다시 호출하지 않습니다. 정확한 ID·정책·
활성 상태의 재판독과 기존 원문 보존은 계속 요구합니다. 복구 준비 안에서 같은 자료를
반복해 읽는 부분도 줄였지만, 변경 전 확인과 변경 후 최종 검증을 생략하지 않습니다.

앞선 실패에서 일부 규칙이 이미 변경됐을 가능성도 있습니다. 오류가 났다는 이유만으로
“아무것도 바뀌지 않았다”고 안내하지 않습니다. 남은 기록과 현재 상태를 먼저 대조해야 하며,
설치만으로 기존 방화벽 기록을 지우거나 전체 규칙을 초기화하지 않습니다.

## 2. 오래 기다리는 복구에도 진행 단계와 결과를 남깁니다

복구 조회와 적용에 각각 새 요청 번호를 사용하고, 해당 작업의 허용된 단계와 실제 정수
건수만 표시합니다. 원본 기록 읽기, 현재 규칙 읽기, 기록·규칙 대조, 원본 보관·계획 기록,
원상복구, 검증, 마감 순서를 볼 수 있습니다. 검증 중 재대조 단계는 반복될 수 있습니다.
처리 건수는 해당 단계의 n/m이며 전체 성공률이 아닙니다. 총수를 모르면 불확정 대기로
표시하고, 계산하지 않은 백분율이나 예상 남은 시간을 만들지 않습니다.

전체 경과 시간과 마지막 진행 응답 이후 시간을 나누고, 실패하면 마지막 단계와 건수를
남깁니다. 시작부터 버튼과 중복 클릭을 잠그며, 늦은 이벤트가 다른 작업의 화면을 덮지
않도록 했습니다. 조회 화면의 취소나 610초 대기 상한은 실제 백엔드 작업 취소가 아닙니다.
실제 작업이 끝날 때까지 새 요청을 막고, 적용 결과 판정 이후의 SSH 상태 조회가 끝날
때까지 잠금을 유지합니다. 복구 후 SSH를 자동으로 켜지 않습니다. 복구가 필요한 동안은 바로 켤 수 있다는 안내 대신 복구 안내를 먼저 보여줍니다. 이 안내는 10개 언어에
반영했으며 실제 PC 접속 성공과 화면 진행 표시는 구분합니다.

이미 실행 중인 복구가 느리다는 이유만으로 다시 요청하거나 앱을 강제로 종료하지 마세요.
실제 이중 복구 실행이 발생했다고 단정할 증거는 없으며 기존 화면·백엔드 가드도 보존합니다.

## 3. 비공개 시험에서 넓힌 Windows 방화벽 형식 호환을 포함합니다

0.2.8 이후 시험한 Windows에서는 패키지 앱 규칙이 `v2.33` 형식이었습니다. 기존
`v2.31/v2.32` 판독에 이 형식과 유효한 `Edge`·`Defer` 조합을 추가했습니다. 같은
고유 ID의 원문 정책과 Windows 정책의 값·자료형까지 대조하며, 이름만 같은 앱 규칙을
일괄 예외 처리하지 않습니다. 패키지 이름(PFN)·규칙 ID·원문 대응 확인도 유지합니다.

지원하지 않는 형식·모호한 정책·조회 실패는 계속 차단합니다. 일반 충돌 규칙의 자동
임시 변경 상한은 기존 복구 대상을 포함해 4개입니다. 일반 규칙이 5개 이상인 환경을
자동 처리할 수 있다고 안내하지 않습니다. 원본 정책 해시 형식도 바꾸지 않습니다.

## 4. 이전 방화벽 기록은 확인한 범위만 별도로 복구합니다

과거 기록에는 지금은 SSH 충돌에서 제외하는 패키지 앱 규칙과 현재 정책에 대응하지 않는
항목이 함께 남을 수 있습니다. 「이전 방화벽 기록 복구」는 현재 일반 규칙을 보존하면서
정확한 ID·전체 정책·패키지 조건이 대응하는 규칙만 기록된 활성 상태로 되돌립니다.
현재 찾지 못한 항목이 삭제됐는지 변경됐는지는 추정하지 않으며, 원문과 미해결 상태를
보관합니다. 오래된 기록을 지우는 것으로 보호 검사를 통과시키지 않습니다.

사용자가 표시된 계획을 확인한 뒤 복구합니다. 원문과 진행 기록을 보호 저장소에 먼저
남기고 중간 실패는 같은 계획으로 이어갑니다. 이미 복원한 패키지 규칙을 실패 처리 중
다시 끄지 않으며, 미완료 복구를 일반 SSH 작업이나 제거가 완료 처리하지 못하게 합니다.
복구 자체는 SSH 서비스를 시작하지 않습니다. 복구가 끝난 뒤 SSH 켜기와 실제 연결을
별도로 확인해야 합니다. 0.3.1의 실제 적용 실패는 이번 결과 판독 보완이 필요한 근거로 남깁니다.

## 5. 제거에서는 공유 정리와 SSH 환경 보존을 구분합니다

제거의 공유 정리 선택은 앱이 추적한 회원 연결·계정·권한·공유 등록과 기록된 SMB
설정을 정리하면서 SSH·네트워크 프로필과 해당 원복 기록은 보존합니다. 회원 연결이
종료될 수 있으므로 열린 파일을 먼저 저장해야 합니다. 사용자 파일은 삭제하지 않으며
로컬 앱 데이터 삭제는 마법사의 별도 선택을 따릅니다.

정리가 실패하면 앱과 복구 기록을 남기고 처음 선택한 같은 보존 방식으로 이어갑니다.
일부 정리가 끝났다는 이유로 전체 완료를 표시하지 않습니다. SSH 환경의 완전 원복은
별도 기능이며, 구버전의 전체 원복 중단 기록을 새 보존 선택으로 자동 바꾸지 않습니다.

## 6. 서비스와 재부팅 안내도 실제 상태를 따릅니다

정상 서비스는 실행 상태와 시작 유형부터 읽고 이미 목표 상태면 변경 권한을 요청하지
않습니다. 실제로 바꿀 항목에만 필요한 권한을 사용하고 변경 전 원상태와 결과를 확인합니다.
실행 중이어도 자동 시작이 준비되지 않았다면 완전 적용으로 판단하지 않으며, 선택 서비스의
실패까지 최종 경고에 남깁니다. 일부 서비스가 미완료인데 필수 설정 완료라고 안내하지 않습니다.

재부팅 안내는 관리자 창과 일반 탐색기의 드라이브 표시 정책을 실제 변경했는지와 연결합니다.
구형 기록이나 조회 실패로 알 수 없으면 미확인으로 표시합니다. 자동 설정 전체 시각을 해당
정책의 변경 시각으로 재사용하지 않으며, 최종 응답 이후의 늦은 이벤트가 경고를 덮지 않게
합니다. 이 정책의 반영 안내는 SSH 기록 복구와 별개이며 재부팅만으로 SSH 오류나 모든
설정이 원복된다고 안내하지 않습니다.

## 7. 통신 보안과 보호 교체도 누적합니다

비공개 0.2.9에서 반영한 `rustls 0.23.45`와 공식 권고 `GHSA-2mjx-qc3c-rqvc` 대응을
유지합니다. TLS 1.3 메시지 처리의 보완이며 SSH 방화벽 복구 실패와 별개의 수정입니다.
이번 수정에서는 다른 의존성 버전이나 법률 정본·업데이트 공개키를 바꾸지 않습니다.
실제 COM 동작을 모의하는 시험에는 잠금에 이미 있던 windows-core 0.61.2를 개발용
직접 의존성으로 연결했습니다. 새 패키지나 실행 시 의존성을 추가한 것은 아닙니다.

기존 지원 버전에 더해 비공개 0.3.1의 보호 교체를 설치기 네 진입 경로에 연결합니다.
이전 파일 소유 표식·백업·중단 복구·수동 재설치와 설정·공유·SSH 장부 보존을 유지합니다.
교체가 실패하면 이전 버전과 복구 근거를 보관하며 새 앱 성공으로 표시하지 않습니다.
버전 상수 누락·비정규 버전·소유 표식 오류의 정적·합성 회귀도 함께 보강합니다.

README·보안 고지·한영 사용 설명서·공개 저장소 템플릿과 이 변경일기를 현재 후보에
맞춥니다. 비공개 누적 버전과 현재 공개판을 구분하고, 제거 안내의 오래된 전체 원복 설명도
실제 공유 정리·SSH 보존 선택에 맞춥니다. 제3자 고지와 정확한 MPL 원본은 최종 잠금
그래프에서 생성·검증하며 결과는 최종 검증 기록에 별도로 남깁니다.

## 설치와 앱 내 업데이트

- 설치 파일은 `PCssak-Gongyu-0.3.2-Windows-x64-Setup.exe`입니다.
- 법률 정본과 업데이트 공개키를 바꾸지 않습니다. 정상 법률 동의 기록이 남은 0.2.8 사용자는 앱에서 새 버전을 확인하고 다운로드·서명 검증·사용자 승인 후 업데이트할 수 있습니다.
- 0.1.0에는 앱 내 업데이트가 없으므로 공식 설치본을 한 번 수동 설치해야 합니다.

위 파일명은 공개 계약입니다. 실제 공개 자산이 게시되기 전에는 새 업데이트가 제공된다고
표시하지 않습니다. 현행 법률 동의가 있는 공개 0.2.0~0.2.8과 비공개 0.2.9·0.3.0·0.3.1은
기존 키로 서명한 후속 공개 자산을 검증한 뒤 업데이트할 수 있습니다. 0.1.9는 현행 법률
문서 확인을 위한 대화형 설치, 0.1.8 이하는 이전 공개키 전환에 따른 수동 설치가 필요합니다.
기존 지원 0.1.1~0.3.1은 먼저 제거하지 않고 보호 교체합니다. 0.1.0만 별도 제거 후
설치하며, 동의나 설치 기록을 확인할 수 없으면 대화형 설치 안내를 따르세요.

## 확인한 범위와 아직 남은 확인

개발 Rust x64 시험은 942개 통과·실패 0개·수동 시험 23개 제외, 전체 UI 시험은
426개 통과·실패 0개·제외 0개입니다. COM 모의 시험 두 종류에서 원시 HRESULT와
결과 객체 없는 코드 0의 결함을 수정 전 실패로 재현하고, 수정 후 통과를 확인했습니다.
실제 Windows의 StdRegProv 읽기 메서드 두 호출 비교도 0.12초에 통과했으며 시스템
쓰기는 없었습니다. 이 시간은 해당 읽기 시험의 기록이며 복구 성능 수치가 아닙니다.
NSIS 3.12의 실제 업그레이드 네 분기 1,740사례와 상수 누락 92사례도 통과했으며, 실제 설치나 시스템 변경은 하지 않았습니다.

현 개발 PC에서는 이전 경로도 정상 응답했습니다. 따라서 회사 PC 방화벽 제공자의 실제
실패를 재현하거나 해결했다고 단정하지 않습니다. 최종 소스 14단계, 설치본·내부 앱·
두 서명·정확한 9자산·공개 재다운로드·홈페이지 검증 결과는 개발 시험과 구분하여
후속 마감 기록에 남깁니다. 이전 자동 검사 통과와 실제 0.3.1 복구 실패도 함께 보존합니다.
