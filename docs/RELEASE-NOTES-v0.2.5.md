# PCssak Gongyu 0.2.5 — 무료 Early Access

0.2.5는 이미 설치된 SSH를 다시 켤 때 스토어 앱 규칙을 충돌로 오판하던 조회 오류를 수정합니다.
방화벽 사전 점검과 실제 적용이 같은 고유 규칙 ID 계획을 사용하며, 기존 임시 변경 상한과
원복 검증을 유지합니다. PCSSAK 관리 흔적이 없는 기존 SSH는 별도 서비스 시작·중지로
다루며 설치·방화벽·SSH 설정·자동 시작 유형을 보존합니다. 기존 설정의 네트워크 노출 범위를
PCSSAK의 같은 LAN 보호로 표시하지 않습니다. 중단 복구 버튼과 오류 목록 안내도 수정합니다.

## 설치된 SSH 재시작을 막던 조회 오류

- 방화벽 CIM 클래스의 실제 속성 `AppPath`를 읽도록 고쳤습니다. 이전 코드의 `Program`은
  해당 클래스에 없는 속성이어서 `0x80041017` 조회 실패와 패키지 규칙 오판으로 이어졌습니다.
- 사전 충돌 개수와 실제 변경 계획은 같은 정책 저장소·고유 ID·기존 원복 장부로 계산합니다.
  패키지 전용 규칙 25개와 실제 후보 3개가 섞인 사례, 같은 이름의 혼합 규칙, 반복 끄기·켜기,
  새로운 규칙 추가와 손상된 대응을 회귀 범위에 포함합니다.
- 규칙 이름에 OpenSSH가 있다는 이유만으로 제외하지 않습니다. 실제로 넓게 적용되는 규칙,
  판독 실패, 정책 변경은 계속 점검하며 임시 변경 상한 4개도 유지합니다.
- 이미 설치된 검증된 OpenSSH는 DISM 설치를 다시 실행하지 않습니다. 정상 PCSSAK 활성 계약은
  변경 없이 완료하고, 중단 기록은 기존 설치·설정과 원복 장부를 보존한 채 검증·재개합니다.

## 기존 설치와 PCSSAK 관리 구분

- 검증된 서비스가 있고 PCSSAK 수명주기·방화벽·네트워크 원복 흔적이 없으면 기존 환경으로
  표시합니다. 서비스 전용 시작·중지만 제공하며 기존 설치를 자동으로 인수하거나 초기화하지 않습니다.
- 이 경로는 자동 시작 유형, 방화벽 규칙, 인증 방식·키·포트를 포함한 SSH 설정을 유지합니다.
  원래 시작 유형이 사용 안 함이면 몰래 바꾸지 않고 설정 확인을 안내합니다. 재부팅에는 원래
  시작 정책이 적용됩니다. 서비스 중지가 기존 인증 세션 전체의 종료를 보증하지는 않습니다.
- 이미 PCSSAK이 관리하는 SSH는 기존 설치와 장부를 재사용합니다. 일상 끄기는 서비스의
  중지·사용 안 함과 차단을 검증하며, 완전 원복은 별도 기능으로 유지합니다.
- 설정이 불완전하거나 신원·소유권·공유 전용 계정 보호를 확인하지 못하면 기존 내용을
  일괄 삭제하지 않습니다. 외부 설치의 네트워크 노출 범위는 기존 설정대로라고 표시하며
  PCSSAK의 같은 LAN 보호 또는 다른 PC의 접속 성공으로 표시하지 않습니다.

## 오류 안내와 중단 복구

- 오류 문구 갱신으로 사라지던 복구 카드 이동 버튼을 보존합니다.
- 규칙 목록을 실제로 읽었는지 확인해 목록 위치·목록 미확인·재조회 실패 안내를 구분합니다.
  공용망 전환 원복이 먼저 실행될 수 있으므로 무조건 아무 설정도 바꾸지 않았다고 쓰지 않습니다.
- 중단 작업 재개는 준비됨 화면에서 끝내지 않고 백엔드 검증과 저널 완료까지 진행합니다.
- 기존 서비스 전용 요청도 관리자 확인·앱 잠금·머신 작업 잠금·단일 작업 재개 계약을 사용합니다.

공식 기술 근거: [Microsoft CIM 응용 프로그램 필터 속성](https://learn.microsoft.com/en-us/windows/win32/fwp/wmi/wfascimprov/msft-netapplicationfilter).
현재 PC에서 기존 쿼리의 실패와 교정 쿼리의 정상 반환을 읽기 전용으로 대조했습니다.
첨부된 2번 PC 로그와 합성 회귀는 해당 PC에서 새 설치본의 실제 접속이 성공했다는 증거가 아닙니다.

## 설치와 앱 내 업데이트

- 설치 파일은 `PCssak-Gongyu-0.2.5-Windows-x64-Setup.exe`입니다.
- 법률 정본과 업데이트 공개키를 바꾸지 않습니다. 정상 법률 동의 기록이 남은 0.2.4
  사용자는 앱에서 새 버전을 확인하고 다운로드·서명 검증·사용자 승인 후 업데이트할 수 있습니다.
- 정상 법률 동의 기록이 있는 0.2.0·0.2.1·0.2.2·0.2.3도 동일한 검증·사용자 승인 절차로 앱 내
  업데이트할 수 있습니다.
- 0.1.9는 현행 법률 문서 확인을 위해 공식 설치본을 직접 실행합니다. 0.1.8 이하는 앞서
  고지한 업데이트 공개키 전환 때문에 공식 설치본을 한 번 직접 실행해야 합니다.
- 0.1.1~0.2.4는 먼저 제거하지 않습니다. 새 설치기가 기존 앱 파일을 보호 교체하며 사용자
  설정·법률 동의·공유 장부·SSH 복구 기록을 보존합니다. 0.2.4 허용을 이전 파일 백업,
  중단된 설치 복구, 대화형 교체, 재설치의 네 진입 분기에 추가했습니다.
- 0.1.0에는 앱 내 업데이트가 없으므로 공식 설치본을 한 번 수동 설치해야 합니다.
- 이미 제거했다면 새 공식 설치본을 사용하되 Windows 복구 기록을 임의로 지우지 마세요.
  앱 교체와 SSH 초기화는 다릅니다. 0.1.0만 별도 수동 제거 후 설치 대상이며, 새 동의가
  필요하거나 설치 기록이 손상됐다면 대화형 설치로 안내합니다.

## 안전·지원 및 검증 범위

공개 설치본은 Windows x64 전용입니다. PCSSAK 관리형 SSH는 신뢰하는 같은 물리 LAN용이며 VPN·가상
어댑터를 신뢰 범위에서 제외합니다. 관리자 권한과 공용 물리 LAN 신뢰의 필요한 동의를
유지합니다. 카페·호텔·공항·게스트 Wi-Fi를 신뢰 LAN으로 전환하지 마세요.

PCSSAK 관리 경로는 기존 OpenSSH를 재사용합니다. 관리형 켜기는 서비스 실행·자동 시작을 함께 확인하고, 끄기는
서비스 중지·사용 안 함 시작 유형·보호 규칙을 확인합니다. 완전 원복은 별도 기능이며
앱이 직접 설치한 소유 증거가 있는 OpenSSH만 제거 대상입니다. 사용자 설정·외부 규칙을
일괄 삭제하거나 방화벽·보안 제품·조직 정책을 해제하는 방식은 사용하지 않습니다.

PCSSAK 관리 경로에서 실제 외부 허용 규칙이 상한을 넘는 PC에서는 SSH 켜기가 진행되지 않습니다. 이는 결함이 아니라
Windows 기본 규칙을 대량으로 변경하지 않기 위한 의도된 실패 폐쇄입니다. 화면에 표시되는
규칙 목록을 관리 담당자와 검토하거나 그 PC에서 SSH를 사용하지 않는 선택을
할 수 있습니다.

Windows Authenticode 게시자 서명이 없습니다. Tauri 업데이트 서명·독립 Minisign 서명·
SHA-256은 무결성을 검증하지만 Windows 게시자 신뢰를 대신하지 않습니다. Windows나
보안 제품이 실행을 막을 수 있습니다. 보안 프로그램을 끄지 마세요. 해시·서명이 다르면
실행하지 마세요.

관리자 승인으로 `0.1.2 <= 버전 <= 0.4.9`는 무료 공개 Early Access로 제공합니다.
생산 화면·메모리 회귀와 실제 NSIS 엔진의 합성 분기 시험은 실제 제품 설치·SSH 접속 시험이 아닙니다.
최종 동결 소스의 Windows 로컬 14단계, 같은 소스의 빌드와 두 업데이트 서명, 법률 정본·
MPL 원본·정확한 불변 9자산 검증을 공개 전에 별도로 결속합니다.

- Windows 10/11 Home·Pro 전체 실기 검증이 완료되지 않았습니다.
- 실제 두 PC의 SSH/SFTP 실기 검증이 완료되지 않았습니다.
- 외부 법률 검토가 완료되지 않았습니다.
- 독립 공급망 검토가 완료되지 않았습니다.
- 실제 사용자 PC의 설치·일반 제거·공유 연결·SSH 로그인·SFTP·재부팅 지속성은 배포 후 확인합니다.
- 제보 PC에서 이번 수정이 실제로 SSH 접속을 성공시켰는지는 아직 실측하지 않았습니다.

복구 가능한 시험 PC에서 최신 백업과 함께 사용하세요. 조직 정책, 설치 원본 부재,
다른 서비스의 포트 점유, 계정 인증 실패까지 항상 자동 해결한다고 보장하지 않습니다.
제보 사진과 다른 PC의 환경을 같다고 추정하거나 미실행 시험을 통과로 표시하지 않습니다.
