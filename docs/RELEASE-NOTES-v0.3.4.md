# PCssak Gongyu 0.3.4 — 복구 기록을 지키면서 멈춘 지점을 구분하는 변경일기

## 이번 변경을 시작한 이유

0.3.3을 사용한 PC에서 이전 방화벽 기록 복구 조회가 다시 실패했고, 재부팅 뒤에도
SSH 설정을 끝내지 못했다는 보고가 이어졌습니다. 규칙을 읽는 화면이 오래 유지된
경우도 있었습니다. 앞선 버전의 자동 검사와 공개 파일 검증이 실제 PC의 복구 성공을
보장하지 않는다는 점을 다시 확인했습니다.

확보한 로그에서는 저장된 복구 계획과 현재 관측의 비교 단계까지 도달한 실패를
확인했습니다. 다만 어떤 실제 규칙이 달라졌는지, 대기 시간의 대부분이 어느 Windows
호출에서 생겼는지는 기존 기록만으로 확정할 수 없었습니다. VPN 설치 여부나 특정 제품의
규칙 이름을 직접 원인으로 단정하지 않았습니다.

이번 0.3.4는 **같은 상태를 다르게 판단할 수 있던 비교, 불완전한 목록 판독,
실패 위치를 충분히 설명하지 못하던 진단**을 보완합니다. 기존 기록을 지우거나
방화벽을 초기화해 복구를 건너뛰는 변경은 아닙니다. 제보된 PC의 문제가 모두
해결됐다고 발표하는 버전도 아닙니다.

## 같은 규칙의 조회 순서와 실제 변경을 구분합니다

Windows가 같은 규칙을 다른 순서로 돌려줘도 전체 목록이 다르다는 이유만으로
복구를 거부하지 않도록 비교를 보완했습니다. 새 계획의 순서는 정확한 규칙 ID를
기준으로 고정하고, 기존 계획은 원문을 다시 저장하지 않은 채 의미를 비교합니다.

ID 집합, 정책 해시, 활성 상태, 이관 정보와 기준선을 따로 확인합니다. 실제 규칙이
추가·삭제되거나 ID·정책·활성 상태가 달라진 경우에는 계속 중단하며, 중복 ID나
불명확한 대응을 정상으로 취급하지 않습니다. 외부에서 생긴 새 규칙을 앱이 변경했던
대상으로 가져오거나 오래된 제3자 규칙을 임의로 다시 만들지 않습니다.

V4 기록에서 같은 뜻의 표현을 대조할 때도 기존의 주소·포트·경로·프로필 비교 기준을
사용합니다. 비교를 위해 원본 문자열이나 승인 해시를 새 값으로 바꾸지 않습니다.
저장된 값만으로 알 수 없는 과거 속성은 추측해서 채우지 않습니다.

복구 적용 전과 항목별 변경 뒤의 정확한 규칙 재판독, 원문 확인, 중단 체크포인트와
최종 검증은 유지합니다. 이미 확인한 원복을 실패 처리 중 다시 되돌리거나, 새로운
조회 응답 없이 오래된 승인으로 다음 변경을 시작하지 않습니다.

## 빠진 규칙을 완전한 목록으로 취급하지 않습니다

COM 방화벽 열거에서 반환 상태와 개수를 확인하고, 지원하지 않는 항목 형식,
빈 인터페이스, 규칙 인터페이스 변환 실패와 개수 한도를 각각 구분합니다.
이전에는 항목 변환 실패를 건너뛸 수 있었지만 이제 불완전한 목록으로 안전 판정을
계속하지 않습니다. 정상 마지막 항목과 정상 종료는 보존합니다.

속성 읽기에서는 정상적인 빈 값과 읽기 실패의 기존 의미를 유지하면서 고정된 속성
단계와 숫자 오류 근거를 남깁니다. 읽지 못한 값은 기존처럼 판독 실패 상태로 남기며, 빈 문자열과 같은 뜻으로
통일하지 않습니다. 모든 속성을 읽지 못해 SSH 관련 근거도 얻지 못한 규칙을 새로
전부 차단하는 변경은 아니며 기존 후보 판정의 한계는 남아 있습니다. 진단만으로
Windows 설정이 손상됐다고 판단하거나 모든 속성 관측의 완전성을 보증하지 않습니다.

## 오래 기다릴 때 어느 일을 하는지 보여 줍니다

복구 진행 화면은 기존 기록·비교·원복 단계에 다음 다섯 실제 조회 단계를 더합니다.

- Windows 정책 제공자 연결
- 방화벽 규칙 목록 조회
- 방화벽 규칙 속성 읽기
- 정책 저장소 조회
- 정책 상세 속성 읽기

열 개 언어의 문구를 함께 맞췄습니다. 실제 보고받은 단계만 표시하고 전체 건수를
모르면 미확정 상태로 둡니다. 시간이 흘렀다는 이유로 처리 건수나 완료율을 늘리지
않습니다. 언어 변경도 마지막 진행을 다시 그릴 뿐 Windows 조회를 새로 실행하지 않습니다.

요청에 연결한 제공자 단계와 경과 시간은 대기가 생긴 위치를 찾기 위한 진단입니다.
규칙 이름, 경로, 계정, 주소나 쿼리 원문은 이 새 진단에 넣지 않습니다. 물리 LAN
관측, COM 목록 판독, 정책 읽기, 복구 계획의 ID·정책·활성 상태 변화도 고정된
화면 코드로 구분합니다.

대기 취소 뒤 실제 읽기 작업이 끝날 때까지 재입력을 막고, 늦게 온 응답이 동의창이나
변경 작업을 열지 않는 보호를 유지합니다. 실패하면 마지막 실제 단계와 확인된 건수를
남깁니다. 화면 대기 종료는 Windows 호출의 강제 중단이나 복구 완료를 뜻하지 않으며,
이번 계측만으로 모든 공급자 지연을 없앴다고 보장하지 않습니다. 반복 조회가 로그와
화면을 과도하게 갱신하지 않도록 상세 기록 수와 진행 이벤트 빈도를 제한하며,
실제 마지막 단계와 종료 사실을 보존합니다.

## 기존 설치와 업데이트 경로를 보존합니다

설치기에 공개 0.3.3에서 0.3.4로 보호 교체하는 네 진입 경로를 추가했습니다.
버전 분기 누락, 잘못된 버전 문자열, 소유 표식 불일치, 교체 실패와 중단 뒤 복구를
회귀시험에 포함합니다. 이 시험은 제품을 실제 설치하는 시험과 구분합니다.

Cargo·Tauri 제품 버전, 설치본에 포함되는 보안 안내, 한영 사용 설명서, 공개 문서와
자산 계약을 0.3.4로 맞춥니다. 의존성 버전·법률 정본·업데이트 공개키는 바꾸지 않습니다.
제3자 고지와 MPL 원본은 최종 잠금파일과 실제 버전에 맞춰 생성·검증해야 합니다.

## 설치와 앱 내 업데이트

- 설치 파일은 `PCssak-Gongyu-0.3.4-Windows-x64-Setup.exe`입니다.
- 법률 정본과 업데이트 공개키를 바꾸지 않습니다. 정상 법률 동의 기록이 남은 0.3.3 사용자는 앱에서 새 버전을 확인하고 다운로드·서명 검증·사용자 승인 후 업데이트할 수 있습니다.
- 0.1.0에는 앱 내 업데이트가 없으므로 공식 설치본을 한 번 수동 설치해야 합니다.
- MPL 원본 이름: `PCssak-Gongyu-0.3.4-MPL-Sources.zip`
- 공개 대상: Windows x64. Windows x86 설치본은 공개하지 않습니다.

정상 법률 동의 기록이 있는 공개 0.2.0~0.2.8·0.3.2·0.3.3과 비공개
0.2.9·0.3.0·0.3.1 사용자는 실제 공개 후 앱에서 다운로드·서명 검증·사용자 승인형
업데이트를 사용할 수 있습니다. 0.1.9는 현행 법률 문서를 확인하는 대화형 설치,
0.1.8 이하는 이전 공개키 전환에 따른 수동 설치가 필요합니다.

0.1.1~0.3.3은 기존 앱을 먼저 제거하거나 설정·공유·SSH·중단 기록을 지우지 않고
보호 교체합니다. 0.1.0만 별도 제거 후 설치하며, 동의·설치 기록을 확인하지 못하면
대화형 안내를 따릅니다. 설치만으로 복구 기록을 삭제하거나 SSH를 자동으로 켜지 않습니다.
이전 불변 릴리스와 자산은 보존합니다.

## 확인한 범위와 남은 확인

개발 중 회귀시험은 의미가 같은 규칙의 순서·표현 차이와 실제 ID·정책·활성 상태 변화,
불완전한 열거, 고정 진단 코드, 다섯 진행 단계와 열 개 언어, 대기 취소·늦은 응답,
설치기의 기존 버전 보호 교체를 대상으로 합니다. 개발 결과와 최종 소스의 필수 검증은
별도로 기록하며, 과거 버전의 통과 수치나 중간 소스의 결과를 새 설치본 증거로 재사용하지 않습니다.

0.3.4의 실제 설치·업그레이드·제거, 방화벽 복구·원복, SSH 켜기·끄기, 두 물리 PC의
로그인·SFTP·공유, 재부팅 후 재접속은 `NOT_RUN`입니다. 제보 PC의 실제 해결과
전체 Windows 호환성도 아직 확인하지 못했습니다. 최종 소스 검증·두 업데이트 서명·
아홉 공개 자산·공개 재다운로드는 각각 해당 절차의 실제 증거로 확인합니다.
이 문서는 그 절차의 완료나 새 버전의 게시 자체를 증명하지 않습니다.

이번 패치는 기존 물리 LAN 전용 SSH 계약과 일반 규칙 변경 상한 4개를 유지합니다.
VPN·가상 어댑터 경유 SSH와 인터넷 포트 포워딩은 지원하지 않습니다. VPN 이름 예외,
외부 규칙 소유권의 전면 재설계, 새 리스너 정책이나 장부 스키마 전환을 완료한 것으로
표시하지 않습니다. 전체 Windows와 두 PC의 실제 복구·재부팅·접속을 계속 확인해야 합니다.

`0.1.2 <= 버전 <= 0.4.9`는 무료 Early Access이며 다음 제한을 유지합니다.

- Windows Authenticode 게시자 서명이 없습니다. Windows가 실행을 막을 수 있습니다.
- Windows 10/11 Home·Pro 전체 실기 검증이 완료되지 않았습니다.
- 실제 두 PC의 SSH/SFTP 실기 검증이 완료되지 않았습니다.
- 외부 법률 검토가 완료되지 않았습니다.
- 독립 공급망 검토가 완료되지 않았습니다.

기존 키의 Tauri 업데이트 서명, 별도 Minisign 서명과 SHA-256은 계속 필수지만
Windows 게시자 신원을 대신하지 않습니다. 보안 프로그램을 끄지 마세요.

복구 가능한 시험 PC에서 최신 백업과 보안 제품을 유지하며 확인하세요. 실패가 반복되면
앱·설정·복구 기록을 보존하고 진단 코드를 확인하세요. 방화벽 초기화, 기록 삭제나 보안
해제로 우회하지 마세요. 모든 환경에서의 무결함·접속 성공·보안 보장을 주장하지 않습니다.
